# 2026-10-16

## RustSpore: reverse engineering SPORE for a Rust/Bevy port

Started the project at `D:\AI\RustSpore` (git repo, first commit `5fa7a98`).
Target data: `D:\Games\SPORE Collection` (GOG repack of the 2009 patched build),
13 `.package` archives totalling about 4.9 GB.

### Settled by measurement

DBPF container format, established structurally rather than from prior knowledge:

- Header: `0x24` = resource count, `0x2C` = index block size, `0x40` = index offset.
  `index_offset + index_size == file size` holds exactly on three packages.
- Index block: 4-byte prefix (always 4), N x 28-byte records, 4-byte trailer.
- Record (7 u32): group, type, instance_hi, instance_lo, offset, stored_size,
  decompressed_size. Field roles separated by value cardinality.
- 136,081 records parse across 10 of 13 archives.

RefPack codec ported to Python (`tools/refpack.py`) and Rust
(`crates/dbpf/src/refpack.rs`). Validated on 800 coded resources across two
packages, each decompressing to exactly the DBPF index's declared size using only
the in-stream header. Two independent sources agree.

### Two hypotheses corrected by measurement

1. Bit 31 of `stored_size` is set on 100% of records, so it is NOT a compression
   flag. The real rule is `stored_size == decompressed_size` means raw.
   (Spore_Game: 2,215 raw, 9,314 coded.)
2. The two `SporeApp.exe` `.text` sections are 93.96% different despite
   near-identical sizes and identical Rich headers. No shared-code claim.

### Open gaps (recorded, not hidden)

- Index layout unknown for 3 packages: `Spore_Audio1`, `Spore_EP1_Locale_01`,
  `Spore_EP1_Locale_02`. The structural search found no valid run in any of them.
  Notably `Spore_Audio2` DOES fit the 28-byte record, so the layout varies per file.
- No RTTI, decompilation or call graph recovered. The REA MCP runs Ghidra headless
  with a 330 s deadline, which a 20 MB MSVC binary exceeds. Tried twice, timed out twice.
- Public sources call SPORE DBPF 2.0 while the u32 at `0x04` measures 3 everywhere.

### Environment blocker

The Rust workspace has never been compiled: there is no C linker on this machine.
No VS/Build Tools, so MSVC's `vcruntime.lib`/`msvcrt.lib` are missing, and
`link.exe` on PATH resolves to PortableGit's GNU `link`. `rust-lld` plus the Windows
SDK libs at `Windows Kits\10\Lib\10.0.28000.0` gets as far as the MSVC CRT symbols
(`_CxxThrowException`, `__CxxFrameHandler3`, `__chkstk`, `_tls_index`, `_tls_used`,
`memcpy`, `memset`). Fix: install VS Build Tools with "Desktop development with C++".

## Second pass (same day), commits ca931e2, 2bee413, c014560

### Index gap closed: all 13 of 13 packages now parse

The three unparsed packages are solved. A unifying invariant holds across every
package: `prefix + record_size + trailer == 36`. Three record variants exist,
differing in size AND field order:

- 28-byte (10 packages): group, type, inst_hi, inst_lo, offset, size, decompressed
- 24-byte (`Spore_Audio1`): type, instance, offset, size, decompressed, group
- 20-byte (both locale packages): hash, offset, size, decompressed, group

Method lesson: **exact fit is not sufficient**. For `Spore_EP1_Locale_02` two shapes
both satisfy `prefix + count*R + trailer == index_size`. The arbiter is storage
contiguity: payloads are packed, so `offset_i + size_i == offset_{i+1}`. `Spore_Audio1`
chains 17,650 of 17,650 pairs with zero gaps, versus 15,730 chains and 1,920 gaps for
the next candidate. `Spore_Pack_03` was used as a control and the method rediscovered
its known layout.

### Engine architecture (docs/engine-architecture.md)

RTTI is **absent** (only 2 type names in a 20 MB C++ binary), so class names came from
string literals instead: 344 simulation classes, 340 ArgScript names, 332 console
commands. Middleware: RenderWare 4 on a DX9 driver, RenderWare Audio plus EAPd
(PureData derived), Havok 3.1.0, Cal3D for skeletal animation, libpng, OpenSSL via
UTFSSL, Tcl/Tk. SPORE is built on EA's shared cross-tree framework (UTFKernel,
UTFNetwork, EASTL), not a bespoke engine. Physics is behind an interface with three
backends (`physics mode <havok | generic | no_collision>`).

### Pipeline proven byte-exactly

13,174 PNG resources across three packages, **every chunk CRC valid**, 214 MB decoded.
A CRC match cannot be satisfied by right-length-wrong-bytes, so this validates the
header parse, index location, field order, raw-vs-coded rule and codec together.

### prop format: attacked, NOT decoded

Established: prop payloads contain length-prefixed UTF-16LE strings, several reading
cleanly (`Details`, `Domes_gear`, `Group_mkmidlegSkinny_0`). NOT established: the value
encoding after each name, so a reader cannot advance between records. The scan fallback
returns truncated fragments (`Def` for `Defense`), proving it lands mid-string. Kept the
tool because its failure is the evidence, but did not present its output as a result.
See `re/payload-formats.md`.

### Rust

New `crates/dbpf/src/index.rs` implements shape detection (exact fit then contiguity
scoring) and per-variant field decoding. Still never compiled: no C linker. Verified
only by brace-balance and reference checks, which is not a substitute for cargo.
One splice bug was caught this way (a dropped brace closing `impl DbpfFile`).
