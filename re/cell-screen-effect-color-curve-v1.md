# Candidate screen-effect color curves

This read-only analysis concerns screen component 186 linked from visual 4930 of the six candidate C1195706 effect-directory payloads in the base PatchData and Spore_Graphics packages, variants 0, 1 and 2. Their paths and individual SHA-256 values are in `target/source-cell/skybox-effdir-payloads-v1/manifest.json`; each retained payload was checked against that manifest before extracting its record. Runtime package precedence, successful loading and selection of this candidate remain unverified.

All six records have the same measured fields: mode 5, flags 1, one RGB sample `(1.0, 1.0, 1.0)`, one strength sample `1.0`, zero distance samples, and four floats `(8.0, 0.0, 0.0, 0.0)`. The independent SporeModder FX [ScreenEffect definition](https://github.com/Spore-Community/SporeModder-FX/blob/master/src/sporemodder/file/effects/ScreenEffect.java) names those four fields lifetime, delay, falloff and distanceBase. The framing is mixed-endian: array counts, scalar float samples and the fixed floats are big-endian, while nested RGB elements use little-endian floats according to the [ColorRGB definition](https://github.com/Spore-Community/SporeModder-FX/blob/master/src/sporemodder/util/ColorRGB.java). The RGB bytes for each channel are `00 00 80 3f`; the strength bytes are `3f 80 00 00`. Existing `cell_effdir_framing_v3` validates record framing but discards these arrays; it does not currently expose the measured curves.

The registered component reader `ABC380` (q474, evidence `ev_1f1a77786e555aeff55c45c4b8be440d946c4f581f645b36ebd8699492e8c24b`) populates arrays at component offsets +10, +24 and +38 and fixed fields at +4C, +50, +54 and +58. `ABC710` (q476, evidence `ev_92edcd2d4280dd08b414dc0dae0c1e27d8b05cd4a450f3bec91019f2fbfcce09`) reads and interpolates the +10 RGB and +24 scalar arrays. For a one-sample array it selects that sample directly, independent of phase. It multiplies RGB by instance fields +34/+38/+3C. The fourth value combines the +24 sample with instance +30 and an interpolation of instance +28/+2C using a supplied argument. Positive component +54 adds falloff; positive +58 causes distance-curve evaluation. Both stored values are zero for these candidates. The +68 callback mapping and actual instance values remain dependent on runtime context.

On successful registration, `ABC5A0` (q480, evidence `ev_8660ae594e15551d708623c12d7c2ca893bde118f48d34afb2b1e5f159ee6fbb`) initializes phase rate to `1 / lifetime` when lifetime is positive and phase to `-delay * rate`: for the candidate values, 0.125 and zero. `ABC710` advances phase by rate times its first argument. If phase exceeds 1 and flags bit 0 is set, it subtracts 1 once; this is not a general modulo operation. Constructor `ABCC20` (q475) initializes instance +28/+2C/+30 to 1.0 but copies +34/+38/+3C from globals 0167A9B0/B4/B8. Their runtime initialization and subsequent changes remain unresolved; executable initial bytes alone do not establish their live values.

Consequently white RGB and strength 1.0 are source-data values for these candidates, but a fully white final RGBA tuple is not established. A diagnostic using white can cite the candidate curves while explicitly identifying runtime multipliers and callback inputs as assumptions. This is static evidence, not a live-game or pixel-accuracy claim. Further work should trace the three multiplier globals, their setters and the callback receiver, then independently validate any implementation and runtime selection.

## Visual block and runtime modifiers

The hash-checked retained payloads each contain visual 4930 with flags zero and exactly one direct type-9 block, pointing to screen 186. Each block has flags zero, LOD range 1 through 254 (upper bound 255 is exclusive in `A71990`), zero LOD-scale entries, all six begin/end emit, size and alpha scales 1.0, and time scale 1.0. These are candidate record values, not proof of runtime activation. The field names follow the independent [VisualEffectBlock definition](https://github.com/Spore-Community/SporeModder-FX/blob/master/src/sporemodder/file/effects/VisualEffectBlock.java).

In the verified executable, `01311650` loads the verified 1.0 constant at `014861D0` and stores it into globals `0167A9B0/B4/B8`. The initializer's address is present at `013DDE48` among similar function pointers, but this alone does not prove scheduling before a particular construction. A literal-address scan found these writes and the constructor's reads; indirect aliases and later runtime changes remain possible. `ABCC20` copies the globals into instance +34/+38/+3C. Vtable slot +1C is `ABC680`; selector 5 copies three caller-provided floats to these fields, selector 4 writes +30, and selector 0x101 writes +28/+2C from the supplied structure. Thus the white default can be overridden.

One conditional indirect creation path `A92B10` (q506, `ev_c38fbb8b9cc5a0245bbd29e845a0aa710b3472c81e34156a35e487e253032008`) sends selector 5 with RGB formed from a 0x4C-byte item's +38/+3C/+40 fields multiplied by parent +170/+174/+178; selector 4 uses item +44 multiplied by parent +180. This path is not established for this direct type-9 block: its enclosing runtime values and application to this candidate are unknown.

The separately traced direct visual path `A71990` → `A70F60` constructs a component, calls slot +18 with transform data, and conditionally invokes slot +8. In that path `A70240` sends selector 0x101 only when the visual block has a nonempty LOD-scale array. Each of these six candidate blocks has an empty array, so this specific branch would skip that setter if the loaded record is unchanged. These observations do not rule out other parameter propagation, later setters, alternate construction paths, or different parent values. The initialized and live final tuple therefore remain unverified.

A bounded static decode of `A82620` adds an important direct-path qualification. After creating eligible blocks, `A71990` can call it. If the visual instance's pointer at +17C is non-null, `A82620` iterates parameter indices 0–24; for each nonzero count it forwards that index, a pointer into the parameter store, and the count to child vtable slot +1C, unless the child's block flags contain 0x20. Index 5 therefore reaches the screen instance's RGB setter, and these candidates' stored block flags are zero. The parameter store's runtime presence and values are not established by the visual record. The call occurs after eligible block creation in the observed static path; subsequent propagation or other callers have not been exhaustively resolved.
