# `_CIasin` fixed-reference host: preparation plan

This is a review plan, not an executable host or a native result. It extends [the static `_CIasin` trace](crt-ciasin-cell-input-static-v1.md). No DLL, original instruction or game was executed for this plan. Runtime DLL selection, live FP state and the selected retail branch remain unknown.

## Fixed input and loader admission

The proposed 32-bit process selects the absolute path `D:\Games\SPORE Collection\SporeBin\msvcr90.dll`, SHA-256 `ed0170d3de86da33e02bfa1605eec8ff6010583481b1c530843867c1939d2185`, x86 PE32, 655,872 bytes, version `9.00.21022.8`. `_CIasin` is unforwarded export ordinal 74 at RVA `7A830h`; the source game thunk's separate IAT identity is in the static trace. A runner must pin its own reviewed executable/source/fixture and the DLL before and after, with fixed trusted paths and no shell. Endpoint hashes do not detect transient replacement, and the caller must admit stable trusted files and directories throughout.

Use a dedicated no-CRT-import x86 host and a fresh process with no preloaded `msvcr90.dll`. Audit the host's complete imports and embedded manifest, executable-directory `.local` redirection, activation context and already-loaded modules. Load the exact absolute DLL with `LoadLibraryExW`, `LOAD_LIBRARY_SEARCH_DLL_LOAD_DIR | LOAD_LIBRARY_SEARCH_SYSTEM32`, and reject if flags are unavailable. Those flags restrict the dependency search; they do not override every redirection rule or prove that the path was bound as intended. Microsoft documents both the [search flags and redirection caveat](https://learn.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-loadlibraryexw). Obtain the returned module's full path and file identity, compare it with the admitted file, hash that file, resolve the named export with `GetProcAddress`, and check that its address is module base plus `7A830h`. Reject unexpected modules, altered bytes or path/identity disagreements. These post-load checks cannot undo code that has already run during loading.

Static PE inspection finds one direct import descriptor, `KERNEL32.dll` with 161 entries, no delay-import or TLS directory, no embedded manifest resource, and DLL entry VA `78542D40h` before relocation. This does **not** inventory dynamically loaded dependencies, OS loader behavior or all initializer side effects. `LoadLibraryExW` runs the DLL's process-attach entry and initializers before returning; Windows documents [process-attach behavior](https://learn.microsoft.com/en-us/windows/win32/dlls/dllmain). The initializer and its reachable callbacks, dependency resolution, writes and failure paths must be separately audited and accepted before loading. Do not use `DONT_RESOLVE_DLL_REFERENCES` and then call the export: that does not provide a valid initialized DLL.

## Fixed call and dispatch envelope

The source intrinsic is an x87 convention: place the finite binary32 input in ST0, indirect-call the verified `_CIasin` export, and consume the returned ST0. This is not an ordinary C `float asin(float)` ABI. Implement the sequence in a reviewed x86 assembly wrapper with explicit stack, preserved nonvolatile registers, guarded buffers, checked x87 TOP/tag and masked exceptions. Run each independent case after `FNINIT`, `FLDCW 027Fh` and `LDMXCSR 1F80h`; record before/after CW, SW, MXCSR and EFLAGS, enforce empty input stack, final TOP and clear stack-fault/DF, and retain allowed sticky status. The source caller performs `FSTP` directly to binary32; capture those four result bytes exactly. A separate optional binary64 capture requires a separate reset and call: inserting an `FST qword` into the main call can change sticky flags and is not the source sequence.

For an explicit **SSE2 fixture**, read the initialized enable global at relocated DLL RVA `9D7B0h` before each call, and require it nonzero together with the exact admitted mask state. To control it, a separately reviewed call to the DLL's `_set_SSE2_enable` can be made before FP-state reset, followed by a checked readback; reject if capability/enable does not yield the required state. This is a controlled host policy, not retail dispatch evidence. A **legacy fixture** can similarly request disabled SSE2, verify the global is zero, reset controls/status, and execute a separate corpus; do not infer either path solely from CPU family. Resolve/check the setter export and ABI against the pinned DLL before using it. This plan does not use a branch hook or executable-page patch; its dispatch evidence is conditional on unchanged code/global between read and call.

Start with a fixed, compiled-in finite binary32 corpus containing `+0`, `-0`, signed minimum subnormals, `±0.5`, immediate binary32 neighbors of `±1`, and exact `±1`; include threshold-neighbor cases identified by an independently audited SSE2 branch partition before claiming branch coverage. Reject NaNs, infinities and outside-domain values in this first host. For each case output input bits, result bits, metadata and fixed branch-policy identifier; verify exact count/length, nonaliasing, canaries, return code and any stderr. Do not assert a mathematical or Rust expected value as native evidence before the host's observed output and an independent comparison. CPU model, OS, DLL and host hashes, selected policy, FP state and startup/loader limitations belong in a new exclusive, synced, readback-verified target-only receipt.

## Blocking conditions and alternative

This host is **not ready to execute**. A path check after `LoadLibraryExW` is too late to prevent an unexpected redirected DLL's initializer, and the candidate's own initializer and possible dynamically loaded dependencies have not been fully audited. Before a direct-DLL run, establish a trusted stable host directory and activation/redirection state, audit the pinned DLL's process attach/initialization and relevant external calls, verify the exact setter/global and x87 wrapper ABI, then independently review the complete fixed host and a bounded hidden runner. If that pre-load boundary cannot be established, do not use direct loading as a reference.

The narrower fallback is a separate no-DLL original-instruction **legacy-path** fixture, not a software translation: map only the pinned legacy code/data spans and explicitly supplied globals under `target`, preserve preferred addresses or audit relocation, and use a fixed `|x| < 1` finite corpus with CW `027F`, MXCSR `1F80`, known empty x87 stack and masked exceptions. First enumerate every reached instruction, direct/indirect target, absolute data reference and error/return branch, including classification and `785BC614`-dependent return handling. Stub nothing opaque; reject any case leaving the audited allowlist. Verify copied and linked bytes, memory permissions and output/FP checks independently before running it. This fallback would establish only that bounded legacy operation on the admitted machine, not default SSE2 output or a live game path.
