# E6A2B0 relation-5 submission: controlled comparison plan

This is a static plan, not an execution result. It follows [the tail trace](cell-feeding-tail-e6a2b0-static-v1.md) for `SporeApp.exe` SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. The previous fixed-nonzero `E6A250` test covered the direct priority-22 path only. This plan targets the separate `PendingSubmission` boundary in `cell_feeding_tail_e6a2b0_v1`, without pretending to execute the real external functions.

## Controlled path and required observations

1. Fix relation to 5 and provide non-aliasing, bounded actor A and B storage extending at least through offsets `+108` and `+10C` respectively, surrounded by canaries. Supply A ID and B `+10C` as different 32-bit words. Do not reuse the smaller direct-path actor buffers.
2. The first patched `E6A250` call must invoke an instrumented stub that records the actor pointer, call ordinal and its own return value, then returns zero without writing actors, selection or geometry. The observed log must contain the expected actor pointer and first ordinal. This is an admitted controlled result, not a claim about the real callback.
3. The original code next reads A ID and B `+10C` and branches on their comparison. Then patched `E4CB40(0x17)` must call a second stub recording ordinal and the literal argument `0x17`. Return a fixed word distinct from the A `+108` word as read **after this call**; stub purity and non-aliasing are explicit admissions. The resulting unequal branch skips `E571C0`. Patching that and every other unsupported external call to a reviewed fail-closed trap is required.
4. Exercise `+20 == 0` and at least two nonzero words independently. The next source call to `E59B40` must go to a third controlled recording stub. That stub records its ordinal and all nine ABI arguments, including both feature words, the exact pushed binary32 depth, selector and pointers; it must not mutate output or the supplied buffers. The expected final log is exactly `[E6A250, E4CB40, E59B40]` with one call each, in that order. Both E59 call sites may target the same stub. The source function must return with all canaries intact and the complete output unchanged. Compare the recorded selector, actor IDs, feature words, depth and copied point/normal contents with the model's `PendingSubmission` candidate; compare all twelve output words against the original snapshot as a separate assertion.

`E6A2B0` uses `FLD`/`FSTP` for this submission, unlike the previously tested direct path. Set, record and restore a deliberately admitted x87 control word with masked exceptions and a known empty x87 stack; use finite binary32 values, signed zeros and subnormals, and check the control word and stack discipline after return. This does not claim the retail environment has that state. Keep MXCSR `1F80`, use explicit per-call debugger checks and enforce the same no-debugger, stable-file and timeout limitations as the existing reviewed host. Neither canaries nor post-build receipts are guard pages or hermetic build proofs.

## Safety and sequencing gate

The recording stubs need a bounded writable log disjoint from executable memory, source buffers and output. Runtime-patched absolute log addresses must be validated against the actual linked x86 host; `CALL rel32` relocation, all argument offsets, register preservation, stack cleanup, flag effects, stub return addresses and canaries need instruction-by-instruction independent review. The E59 stub has nine arguments; it must not assume a C calling convention merely from decompiler names. Log overflow, wrong order, unexpected actor/definition identity, unexpected external calls, nonfinite input, debugger detection, API failure and host faults must fail before any model comparison. The INT3/UD2 trap is only fail-closed under normal unhandled-exception behavior, and a debugger could attach after the check.

Generate a fresh source-derived host, linked x86 host, adapter and runner; pin their bytes and all source, patch, tool and receipts separately, preserve every preparation failure and use a unique result directory. Independent review must happen before any relocated original instruction or stub is executed. The test can validate the transfer to the pending-candidate boundary only; testing actual E59 arbitration is a later independent step, with a further fresh state snapshot and separately admitted call. It cannot establish real `E6A250`, `E4CB40`, `E571C0`, callback effects, actor lifetime, feature geometry, event scheduling or gameplay.

The other relation-5 branches remain outside this test: ID equality direct write, matching definition followed by `E571C0`, and external mutations changing any subsequently read actor or output field. Those need separate ordered stubs, snapshots, or original-instruction evidence before integration. No code or original instruction was run to prepare this plan.

## Additional safety gates from independent plan review

The reviewer confirmed the proposed ordered calls and ABI, subject to the following gates. Actor A must expose at least `0x10C` bytes from its passed pointer, including the complete four-byte `+108` field; B must expose at least `0x110` bytes, including complete `+10C`. Surrounding canaries detect only some writes: they are not guard pages and do not detect reads beyond the admitted range. Non-aliasing and full buffer lifetimes are required.

The host must preserve nonvolatile registers at every stub and verify the source call's original x86 ABI stack balance. Enumerate and independently verify all five original `CALL rel32` patches: offsets `0x12` (`E6A250`), `0x32` (`E4CB40`), `0x43` (`E571C0`), `0x7A` and `0xA4` (the two `E59B40` sites). The three admitted stubs must append into a fixed-capacity log, reject overflow and unexpected sequence before any write past the log, and trap or return a failure for all other targets. Before dereferencing any logged pointer, check its exact equality to the corresponding caller-owned point, normal, actor or output pointer and check the complete range is within its admitted buffer. A pointer copied from the source stack is untrusted until validated; do not dereference arbitrary addresses to create the comparison record.

The x87 requirements are stronger than merely masking exceptions. Before the source call, establish an empty x87 register stack with known tag state and TOP, masked exceptions, controlled rounding/precision, and preservation of finite binary32 subnormals. Save the entire caller floating environment, including control, status, tag/TOP and pending exceptions, and restore it after the experiment. The test must not silently clear an unmasked pending exception or leave a changed status in the caller. `FNSTENV` itself masks exceptions, and `FNINIT` clears stack/status, so a host cannot use either as an unqualified inspection step and then claim no mutation. Define a reviewed admission and recovery sequence first, including failures and asynchronous faults; explicitly distinguish a deliberately isolated test thread/process with a freshly initialized environment from preservation of an arbitrary caller environment. Capture and verify the admitted before/after x87 status, tag and TOP, and restore the original state under the selected policy. If that protocol cannot be implemented and independently audited, stop before execution; the earlier MXCSR-only host does not satisfy it.

Until these x87 and log protocols are specified in executable, reviewable detail, no new host is considered safe to build or run. This is an intentionally unresolved gate, not evidence of an unsupported native function.

These are controlled substitutes, not recovered callback behavior. The source is not a complete host, has not been compiled, and requires independent review of its ABI, assembler encoding, log address/lifetime, trap behavior and capacity.
