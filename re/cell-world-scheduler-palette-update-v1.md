# Cell world scheduler to conditional animation update

Static source evidence for executable SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. Selective Ghidra 12.1.4 `-noanalysis` decompiled `E53960` (`E53960..E53999`) and `A06600` (`A06600..A06D46`) successfully in `target/ghidra-cell-world-scheduler-v1/`; a separate project `target/ghidra-cell-tick-v1/` decompiled `E806E0` (`E806E0..E809A0`). PE-mapped Capstone instruction bytes are retained in each directory. Import warnings and missing library links were reported. Manual function bodies and decompiler types are limited evidence, not complete xrefs or runtime traces; no original instructions were executed. The world table mapping and constructor identity are conditional on the standard initialization documented in `cell-animation-owner-palette-draw-static-v1.md`.

On one branch through `E806E0`, the direct calls at `E808D7`, `E808DF` and `E808EC` invoke `E7F3D0`, `E73F90` and `E53960` in that order. After `E53960` returns, calls at `E808FE` and `E8090D` invoke `E5FEE0` and `E6CA50`. The branch predicates, complete semantics of these callees and scheduler entry thread are not established merely by this ordered call sequence. Do not identify any one of those calls as a final GPU draw without its own trace.

`E53960` obtains the background animation world from the object at global `016B4BE8` +161C4, calls its virtual +24 with the supplied float and zero, then re-reads the global/root, obtains main animation world +161D0 and does the same. The background callback can therefore affect the later root or world lookup. This is background-before-main only when both pointers and virtual dispatches are valid and return. The earlier Cell construction trace identifies those world roles under its standard setup; replacing the object or vtable invalidates that association.

For the standard table `01449A80`, direct PE table words identify virtual +24 = `A06600`, +28 = `A0C540`, and +2C = `A06310`. At `A06606..A06610`, equal +24/+28 vector pointers return without either later virtual call. On the nonempty route, `A06616..A06629` calls the object's virtual +28; after a separately bounded per-row loop, `A06D29..A06D3D` calls its virtual +2C with supplied arguments. If the +28 callback changes the initially nonempty collection to empty, the later +2C call is still reached on the inspected control flow. Under the same unchanged standard vtable and a normal return through both calls, this conditionally reaches the two-pass `A06310` order documented in `cell-animation-update-draw-order-v1.md`. Its range, object pointers, +184/+17C consumers and lifetime must be valid, and collection mutation across calls is not excluded. `A0C540` semantics and any callbacks or intermediate scheduling remain independent gates.

This closes a concrete conditional path from a Cell-stage callsite to animation-world update for background then main; it does not establish that a particular Jawhead actor was present, that its clip or pose succeeded, that the pointer remained live, or that `73FD30 -> 73EDF0` draw occurred after it. The next source evidence target is to trace the subsequent `E5FEE0`/`E6CA50` callees and the engine's draw submission and synchronization, with their actual object identities. A bounded fixture may mirror this explicit order with caller-supplied stable world identities, collection snapshots and admitted outcomes, but remains an engineering fixture rather than an original frame.
