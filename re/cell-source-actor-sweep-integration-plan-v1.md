# Cell source actors to sweep: integration boundary

This is an implementation plan grounded in [the actor-pool trace](cell-actor-pool-handle-static-v1.md), [the sweep comparison](cell-source-sweep-model-v1.md), and [the source health and contact trace](cell-source-health-integration-proposal-v1.md). Native observations refer to the installed `SporeApp.exe` SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. The checked pool and sweep are bounded models, not evidence of original runtime actor selection or a complete source Cell stage.

## Existing integration boundary

`cell_game.rs` currently uses source Cell assets as inspection art while constructing the prototype `CellWorld`; it does not give the source definition or source pool to that world. `SourceCellLibrary::definition` reads an explicitly supplied CELL ID using the library's documented inspection package order, parses `CellRecord`, then requires a structure with a single baked creation. `CellRecord.raw` preserves the full source definition bytes, which `spore_core::cell_definition::parse` can read for primitive fields. This is sufficient to construct an explicitly selected, asset-backed **test definition**, but not to prove the live game's selected player or resolve every food definition: structure/baked requirements are art-path restrictions and the four-package inspection order is not verified native overlay precedence.

In the native player creation path `E750F0`, the object returned by `E4CCA0` contributes +34 as the fourth argument to `E74A50`; that creator resolves the supplied definition handle, allocates a pool actor and initializes +244 to six. It returns an actor handle which the caller stores at global +411C. `E4CCA0` itself passes global word `015A858C` to `E823D0` (`E4CCA0..E4CCB4`); `E4CB40` indexes the same table in 16-byte steps. `E823D0` acquires through the resource-handle object and returns an interface's +14 data pointer. That word is a **resource handle**, not automatically the CELL resource instance ID, and its +34 field is read after native load/fixups. The serialized source ID, resolved provider/key, resource handle, data-pointer lifetime, and selected actor-pool handle are distinct identities. The table's initialization, actual +34 field identity, native mount winner and player-creation invocation are still unproved. Do not promote the CLI's explicit art ID to the original player selection.

## Minimal admitted actor and join

A source-mode actor record sufficient to feed the bounded sweep must retain:

1. A checked actor-pool handle and pool identity, plus an explicit admitted definition binding containing the exact package/key, digest and raw CELL bytes. Keep the source definition/reference handle separate from the package key and checked actor handle. Resolve/retain the source definition before any actor consumer; fail explicitly on an unsupported or missing binding. For actual runtime behavior, reproduce native fixups and mounted-provider resolution first.
2. Actor +244 as its own integer state, initialized to six only on the corresponding admitted creation route; do not derive it from prototype `health`, mass or `CellFood`. Retain the current player handle as a separately established source state, never infer it from index zero, CLI art choice or largest actor.
3. The current source actor inputs required by `E6D7F0`: +FC/+100/+104, +4C/+50/+54, +58, +48 and, when bit 1 is set, +5C..+7C. A nonzero +FC also requires the correctly resolved live `E67A50` result's +1238..+1244 values and lifetime. Geometry must be computed in source operation order; raw model bounds or the preview's fitted Bevy transform are not substitutes.
4. The collection registration gate and tag inputs from `E74F5B..E75036`, including its comparison against global +40FC and the supplied tag / definition +B4 branch. Track actor +364 and its removal/update lifetime. The input coordinates for `SweepSlot` are the 2D center plus/minus source scalar for the admitted registration, and its `id` is the actor handle bit pattern reinterpreted as signed i32; tag stays the exact source word.

After source-specific registration/update is established, preserve the source pair-buffer capacity and source update order, call the bounded sweep only if its unique finite-normal-or-zero endpoint restrictions and non-mutating snapshot are admitted, consume `dispatch_order`, convert each signed pair word back to its u32 bit pattern, and resolve both through the **same checked actor pool** immediately before evaluating `E7F290`'s strict 3D gate. A stale or cross-pool identity is an explicit checked error; it is not a reason to substitute a different actor. The current sweep rebuild does not model incremental endpoint merge, tied endpoints, tag/slot reuse history or mutation while iterating, so it must not be treated as an interchangeable implementation of the original persistent collection without a source-bound equivalence gate.

## Smallest meaningful integration increment

Add a separate source actor registry and definition-only source reader to the actual Cell application/update architecture, preserving full resource identity and source data; do not make successful definition lookup depend on a baked artwork structure. Add an explicitly selected, labeled fixture mode that allocates checked actor records with supplied counter, source-field snapshots, definition identities, registration inputs and source player handle. It can run a single source-ordered pool-to-sweep-to-checked-resolve handoff and expose the resulting pair list plus explicit unsupported reasons. Such a fixture is an actual update-path integration test, but its caller-provided actor fields and selection are controlled inputs, not proof of an original gameplay frame. Keep unsupported source-mode operations paused or explicitly pending; do not run prototype feeding on them under a fidelity label.

The first live source-mode patch must additionally establish the native config-table and resource selection, `E750F0` invocation, actor identity/creation and player reassignment, `E67A50` cache and geometry updates, collection insertion/movement/removal and sort tie behavior, `E6A450`/`E6A2B0` feature selection, event scheduling/callback and cleanup, and effects before health/progress commits. The stage update call sequence already has event traversal before the contact pass at `E7F521` and `E7F54A`; preserve it in the admitted route without assuming this proves all scheduling paths. Live rendering, input, saves and evolution remain further gates.

Validation should include installed-definition bytes and exact provenance, independent source-bound actor creation and geometry comparisons, same-pool stale-handle and slot reuse cases, signed handle ordering, pair-buffer saturation, unsupported ties and endpoint mutations, and a cross-stage test that verifies reverse pair traversal and re-resolves actors after changes. Then verify actual input/update/observable behavior in a headless running application. Synthetic snapshots, model agreement and an asset-backed record alone do not establish original actor selection, gameplay reachability or 1:1 fidelity. No game, GPU, Cargo or UI code was run in preparing this plan.
