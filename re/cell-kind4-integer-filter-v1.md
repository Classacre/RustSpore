It does not establish active metadata registration, a query outcome, a Cell actor or a runtime pose. The conditional sidecar reader-to-index path is in [the reader note](cell-kind4-metadata-reader-index-v1.md).

The conditional `DDDD0001` and `DDDD0000` conditions use `5589A0`; that constructor stores the supplied start and end directly. In `E84FA0`, the corresponding upper-bound inputs are capped at 10 and incremented before constructing these ranges; negative and sentinel handling and the global-state adjustments are conditional on the source branch.

At the `E84FA0` entry, the stack arguments after the output pointer are, in order, row +14, adjusted row +18, row +0C, and adjusted row +10 from the selected type-1 list entry. `E8501A..E85071` uses the latter pair for `DDDD0001`; `E850C9..E85119` uses the former pair for `DDDD0000`. For each pair, if both bounds are negative the corresponding condition is omitted. Otherwise the lower input is raised to at least zero, upper `-1` becomes 10, the upper is capped at 10, and one is added to form the exclusive endpoint. Adjustment of row +18/+10 by global state happens in `E5C0F0` before this call and is not modeled by this observation.

The manager's `5621B0` uses the condition field to find an integer entry in its +F4 index, then passes its start/end to `564FE0`. `5658F0` calls `4E9230` for each boundary; the latter compares indexed values with signed `setl` and returns the first element not less than the supplied boundary. Thus the value lookup selects the signed half-open range `[start, end)`. `564FE0` combines the selected indexed-value row lists through `567590`; `562320` intersects the resulting list with the working candidates. The special `02DD90AF` range therefore selects integer value `3D97A8E4` when that value is registered for the field.

The retained scan reports 42 source metadata payloads with section-zero integer marker `02E1A75D` and `02DD90AF=3D97A8E4`. Those rows satisfy this particular value test **if** they are read into the relevant active index. None of the 42 payloads contains a literal `DDDD0000` or `DDDD0001` field in either scanned section. That does not determine the complete query result: dynamic producers, other registered values and runtime context can contribute to the index, and the source rows and sidecar reader were not observed running. When a queried field is absent from the relevant index, the condition cannot obtain a matching integer row list through this lookup; this conditional observation does not establish that either field is absent at runtime.

An independently testable, bounded pure projection could accept explicit already-adjusted integer pairs, explicit per-field sorted value-to-ordinal lists and an explicit initial candidate set. It could construct the three ranges above, union ordinal lists for signed values within each range, and intersect each present condition with the candidates. Tests should cover endpoint exclusion, negative signed values, omitted pairs, `-1` upper sentinel, reversed/empty ranges, duplicate ordinals, absent fields and zero candidates. This would test the observed filtering algebra only; it would not discover inputs, reproduce global adjustment or registration, or claim native query selection.
