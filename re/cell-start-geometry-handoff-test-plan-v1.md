Use the existing `matrix` output as the nine physical matrix words and extract the first word of the already asserted chained selected triple (`E219E5D3`) as `ActorInput.handle_fc`. Construct a purely synthetic actor input: position `(10,20,30)` as binary32 bits, scalar `2.0`, flags byte `02`, and the nine-word `matrix`. Supply an explicitly admitted cache snapshot with matching first key, center `(0,0,1)` and scalar `3.0`; use `Policy::Mxcsr1f80`. This deliberately chooses a center along the source's physical third axis. The existing fixture already checks that matrix slots 6 and 7 are zero by magnitude and slot 8 is exactly `1.0`; therefore under the projection's source operand order, finite signed-zero terms added to positive positions leave x and y at exactly 10 and 20, and z is exactly 32. The scalar is exactly `3 * 2 = 6`. Assert output words `[41200000, 41A00000, 42000000]` and scalar `40C00000`, as well as the selected first word and matrix preconditions. These exact simple assertions are independent of host-specific sine/cosine bits, but consequently cover only this chosen axis and do not independently validate the complete matrix or E6D7F0 arithmetic.

Add a wrong-key assertion using the same snapshot with a distinct `key_fc`, expecting `WrongCacheKey`; a missing-cache assertion can expect `MissingCache`. These are checked model policies. A separate `handle_fc = 0` input can assert the direct-copy branch returns the supplied position/scalar without consulting the snapshot or matrix. The rotated nontrivial matrix and signed-zero/underflow arithmetic should continue to be validated by the model's own independent rational comparison, rather than using this simple chain as a general oracle.
