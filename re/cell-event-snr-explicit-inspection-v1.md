# Explicit event-row to SNR inspection

`cell_event_snr_explicit_inspection_v1` accepts an explicit event package, event instance, event payload SHA-256, caller-selected row, SNR package and SNR payload SHA-256. It requires the literal `--admit-loader-complete-unchanged-and-stable-packages` argument. The scope is fixed to `021407EE`; event type is `02B9F662` and SNR type is `01A527DB`. Each exact key must be unique within the explicitly selected package, indexes and payloads are bounded, and both decoded payload hashes must match. Package paths must remain stable while the index reader reopens them; payload hashes do not establish continuous stability or provider precedence.

The restricted count-driven event walk must consume exactly the declared entries and all bytes and contain exactly one `701ED91E` property with type 0020, array marker and nonempty 12-byte raw rows. Every row is checked before selection. The first four selected bytes are interpreted little-endian **under the explicit admission** that the dedicated loader, complete untransformed reads, getter and same native object path in `cell-audio-event-loader-interface-static-v1.md` hold. Zero is rejected because the traced selection path falls back to another word; duplicate sample values remain allowed because the native vector can contain duplicates. The user-selected row is an inspection choice, not a recovered native shuffle, cache state, random draw or active event.

The resulting hash-checked SNR is decoded by the existing bounded vgmstream-derived PCM16 or XAS1 module and a PCM digest is printed; no audio device is opened and no output asset is written. It does not establish native decoder parity, sound completion, a gameplay cue, provider winner or live routing. Unsupported codecs and framing fail closed.

```powershell
tools\build.bat run -p spore-bevy --example cell_event_snr_explicit_inspection_v1 -- 'D:\Games\SPORE Collection\Data\PatchData.package' 34c2ff0b 359d9b975aca87c70e0d4414199893c9819c8a4b4390dc43ff4666838f0a0c12 0 'D:\Games\SPORE Collection\Data\Spore_Audio1.package' f68c6170fcd374eabbc66d7c9d82e10b421cc052570647478ea4f3cc3670afd4 --admit-loader-complete-unchanged-and-stable-packages
```

This checked run selected row 0 instance `B297C8AF`, decoded 44,100 Hz mono 33,165 interleaved PCM values with no loop and little-endian i16 PCM SHA-256 `386ad72e41360d41d7db698d79646015d63a734281820b747a64691dece50757`. This is an explicit inspection of one installed pair, not a native cue selection. Three focused tests passed for byte order, range, zero, declared-count mismatches, high-bit count, unsupported types, inserted separator, native default scalar framing, duplicate properties and malformed stride; real-data invocations rejected bad event hash, out-of-range row, bad SNR hash and missing admission. ## Reader framing correction

The former bridge used `audio_event::parse`, whose advisory-count walk may skip separator-shaped words and can misframe native variants. Native `A19CC0` reads a BE count, takes a separate path if its high bit is set, then reads exactly the masked declared number of entries; `A19520` scalar default for type 0020 requests 16 bytes at `A197D4..E2`, not four. Thus a zero or too-small count could let the old walk find a samples property the native reader would never reach. For the selected installed payload, declared count is three; the general inspection walk produces four apparent entries because it treats the 16-byte parent scalar as a four-byte scalar plus a spurious zero entry.

The bridge now uses its own strict subset of the native instruction framing: no high-bit parent path, no separator skipping, BE declared count, no trailing bytes, scalar types 0009/000A/000D with flags zero and four data bytes, scalar 0020 flags zero and 16 data bytes, and 0020 arrays with flags 001C or 009C and stride 12. It rejects all other types/flags and count or extent mismatches. This excludes many valid native events by design. The selected event's three native-framed entries and the resulting SNR/PCM digest pass unchanged. Even for this restricted framing, native loader/factory, property inheritance, nonzero-versus-full stream reads, cache state and actual provider selection remain explicit admissions. No native code was executed.
