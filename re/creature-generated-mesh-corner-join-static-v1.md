# Creature generated-mesh export: corner and influence join

This is a bounded static trace of the installed `SporeApp.exe`, SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. It identifies an inspectable relationship within one native editor export path; it does not recover the surface generator, prove how a saved GMDL was produced, or assign vertices to CreatureData rows.

The existing [rig analysis](anim-rig-native.md) records the CreatureData block construction, generated body palette and `46E3C0` skin-index conversion. Its comparisons also show that neutral rigid-part assembly does not reproduce shipped merged geometry. [GMDL skin analysis](gmdl-skin.md) documents supported saved vertex influence decoding and rejects ambiguous multi-mesh palette bindings. The source creation's row ordinal, finalized runtime block index, palette index and generated mesh position index must remain distinct identities.

## Native export boundary

The retained Ghidra dossier for `46E3C0` is `target/rea/20261022-anim-rig-finalize-v2/227-analyze_function.json`, evidence `ev_3f4e7f3f56625b5a34da5fe94c4893fd5c9d6cb5d4dc5fc336ea8a11feff1c60`. The editor-related caller `46A100` calls this routine before a subsequent `467F70` call; its dossier is `target/rea/20261022-anim-rig-focused-v1/50-analyze_function.json`, evidence `ev_48b4e2b329b697bf24801a8c2ccd8a0df16f400c8530c6903ae07d16ca6a243c`. The second reported caller is `46B010`. These calls are static, not evidence of an observed save or successful export.

Given valid vectors and pointers, the entry gate compares the count of 20-byte records at input `+7C/+80` against the count of 12-byte position entries at the object pointed to by input `+34`, offsets `+08/+0C`. On the successful branch it iterates the latter object's subobjects in `+E4/+E8` order. Each subobject contains a `+80/+84` array of 12-byte triples and a `+6C/+70` array of 32-bit index values. The corner loop at `46E717..46E776` uses each triple's first word to select a 12-byte position; its second word selects a different 12-byte array; its third word selects entries in two further arrays with 8- and 24-byte strides. It appends the selected attributes to the output. Thus different corner triples can reference the same source position while selecting different other attributes.

At `46E776..46E7DA`, that **same first word** selects a 20-byte input record from `+7C`. Its first four bytes are multiplied individually by three and appended as four 16-bit values; a pointer to the following 16 bytes is passed to an append helper. On the available-capacity branch, `474DE0..474E49` loads and stores those four successive binary32 words using x87. The existing skin evidence interprets the corresponding exported attributes as palette offsets and weights; the arithmetic itself does not prove a CreatureData part index or spatial ownership. The subsequent index loop appends each subobject's indices offset by the output vertex count captured before its corners are appended. Allocation failures, malformed arrays and the grow paths are outside this bounded statement.

## Implementable inspection join and limits

A checked, read-only diagnostic for a supplied **generated intermediate**, if that intermediate can be obtained with a separately established provenance, can enumerate `(subobject ordinal, corner ordinal, position index, other attribute indices, four influence bytes, four float words)` in native order. It should validate all vector extents, divisibility and index bounds, retain floating bits, group corners by position index, and report shared position references and multiple nonzero influences within each selected record without assigning ownership. Under a stable valid snapshot, corners sharing a position index necessarily select the same 20-byte influence record; differing records would indicate invalid or changing input or a diagnostic error. This join follows the same explicit first-index relation above and is independently checkable against a future controlled capture of the intermediate. No such captured input or matching exporter execution is supplied here; the existing saved GMDL decoder is not proof that the transient intermediate can be reconstructed from the saved file.

This does **not** justify changing an existing baked model when a CreatureData part moves. A position index can be referenced by multiple corners; triangles can connect affected and unaffected positions, and multiple nonzero skin influences can make a vertex depend on more than one palette entry. Even a vertex with one nonzero influence does not prove that its palette entry uniquely belongs to the edited source row or that source regeneration would retain the same topology, normals, UVs, morphs, skin and bounds. Replacing only selected vertex positions can therefore leave seams, stale attributes or altered neighboring triangles. The evidence does not establish a generally safe isolated baked-vertex update; the remaining gates include a verified source-row-to-generated-palette mapping, upstream surface and skin producers, source transform spaces, and generation after the edit. A skin-palette pose diagnostic is a separate possible experiment, not a rebake or original editor result.

## Reproduction

Read the retained dossiers above, then independently disassemble the hash-checked PE in x86-32 mode with `pefile` and Capstone at `46E3C0..46E9B0` and `474DE0..474E73` (ends exclusive), mapping virtual addresses by the image base `400000h`. The Ghidra dossier has partial indirect-call coverage; its decompiler is not original source. No game process, GUI, original code execution, Cargo build, creation edit, or generated geometry was used in this investigation.
