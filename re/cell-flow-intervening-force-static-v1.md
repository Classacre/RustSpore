# Cell flow rebuild: E4E4C0 scratch-write boundary

Static x86 instruction inspection of base `D:\Games\SPORE Collection\SporeBin\SporeApp.exe`, SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. This narrows the intervening-call uncertainty in [the flow producer trace](cell-flow-field-producer-static-v1.md); it is not a live execution or a claim of valid runtime field values.

`E4E730` calls `E4E4C0(environment, index)` for indices 0 through 1499 at `E4EA20..E4EA35`. The full `E4E4C0..E4E72D` body has one direct call, to `E4E1A0` at `E4E4FA`; it contains no indirect call or jump. `E4E1A0..E4E21C` directly calls `E4DAF0` and `E4E090`; their inspected complete bodies contain no calls or indirect transfers. Under valid pointers, normal returns and the bounds below, this is the full direct call chain; exceptions, asynchronous mutation and other threads are not modeled.

For the current slot, `E4E4C0` constructs the position pointer `environment + 4 + index*12` and scratch pointer `environment + 1D4D0`. `E4E1A0` uses the position to choose a bin and writes neighbor-bin pointers and counts into caller-supplied stack arrays; `E4E1F0..E4E204` reads scratch counts and computes pointers into its 32-byte records. The consumer reads record position/vector words and a record-supplied index, along with environment scalar arrays `+15F94` and `+17704`. Its persistent writes at `E4E5FC..E4E71E` are exclusively the three words at `environment + D2F4 + index*12`, including a final multiply by the current indexed `+15F94` even when no neighbors are processed. Its other writes are to its own stack or stack-passed output arrays. The current caller's index range makes that persistent output array `+D2F4..+11943`, disjoint from copied scratch `+1D4D0..+3057F` in an ordinary contiguous `30580h`-byte environment allocation.

The first pass of `E4E730` calls the `11E052E` memset thunk with zero and length `1770h` at environment `+15F94`, then writes that array and `+17704`; it calls the same `E4E1A0` neighbor lookup, then runs the 1500 `E4E4C0` calls. The scratch-write conclusion admits a normally returning memset with exactly that bounded destination and length, as well as the other stated nonoverlap and control-flow conditions. Under those admissions, the checked chain supplies no native store to the `+1D4D0` bin counts or copied records between `E4DC40` and `E4DD50`. This supports treating `E4DD50`'s bin inputs as the **earlier copied snapshot**, including the earlier copied scalar, rather than the subsequently written `+15F94` words. It does not prove the snapshot exists in a live game, that no external writer changes it, or that the other environment outputs are unchanged.

This conclusion is conditional on a bounded, nonaliasing layout and valid control flow. In particular, `E4E090` writes the discovered bin list through a pointer without an explicit capacity parameter or check. The relevant caller layouts have room for nine four-byte neighbor entries before adjacent stack locations: `E4E1A0` also constructs a nine-word local list, and `E4E4C0`'s returned count and pointer arrays are `24h` bytes apart. A checked fixture must prove every reached neighborhood result fits those arrays, that scratch bin counts are 0..8 and copied record indices stay in 0..1499, and that finite coordinate/conversion behavior, x87/SSE controls, address arithmetic, object extents and source/output nonaliasing are admitted. The native code does not establish these as universally true for arbitrary global values. A stack overrun, bad pointer, callback outside this chain, alias, exception or concurrent writer invalidates the bounded conclusion.
