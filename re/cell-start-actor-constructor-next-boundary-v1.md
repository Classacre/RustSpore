## New focused observations

For the caller's zero argument 7 and -1 argument 5, `E74A7B..E74AE2` takes the sampled-size branch and loads a multiplier of 1. `4DF9A0` loads the definition's +304/+308 floats as double arguments and calls `4BA080`. The latter computes the difference, calls `935D40` even when the endpoints are equal, then performs x87 multiplication/addition and clamping before the former stores a binary32 result. `E74AC7..E74AE2` divides the 1.0 multiplier by the current global +514C, multiplies by that returned sample and the caller's supplied scalar in x87, and stores the result as binary32. An implementation must preserve the actual x87 precision/rounding and the RNG side effect/order; replacing the equal endpoints by a constant and omitting the call is not a complete model.

`E65640` performs a lookup in the Cell global +5170 cache keyed by its first argument. On a cache hit (`E6565D..E6567D`) it returns the cached value; on a miss (`E6567E..E656A9`) it obtains a cache slot, calls `E5C0F0` with the second argument, copies its returned triple into the cache and returns that slot. This establishes a concrete cache-hit/miss distinction before `E74A50` writes +FC/+100/+104; it does not establish the cache's contents, mutation/ownership, valid supplied handle or actual selection. The explicit candidate's kind-4 row must not be reduced to an arbitrary baked creation.

`E74D12..E74D42` calls `E4F830`, reloads the computed actor scale, then executes two `MULSS` operations and a `DIVSS` to set +B8 and +BC. For the candidate's density zero and cellType two, the two static jump tables select the globals +5C field, but reference acquisition/cleanup and the field's live value are still inputs. This result is not the literal 10 loaded immediately before the call.

## Next source-bound implementation gate

The next tractable slice is the **pre-allocation size calculation** through `4DF9A0/4BA080` and `E74A7B..E74AE2`, with explicit `CellDefinition` size bits, argument-6 bits, global +514C bits, RNG return and before/after RNG state, and a named x87 control word. Compare it against the exact source bytes in an independently reviewed native host over candidate equal endpoints plus non-equal and rounding boundary inputs. Gate nonfinite, zero divisors, unmasked exceptions and unsupported states explicitly. This only returns the source scale and ordered RNG transition; it must not allocate an actor or set a player.

Next recover and compare the null-orientation `935D40`/trigonometric/`59C000` path, and separately model `E65640` cache hit/miss, descriptor-fixed structure and list handle resolution, `E5C0F0` RNG progression, and result lifetime. Follow with `E6CB30`, `E86960` and collection insertion/removal side effects in actual order. Only after those boundaries and a resolved definition handle are available can a partially initialized record be safely admitted to the checked actor pool, with remaining fields clearly staged rather than silently filled. A supplied after-call snapshot is an admissible fixture input for testing a later consumer, but cannot by itself prove those missing transitions or a runnable player.
