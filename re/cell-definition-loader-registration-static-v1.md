# Cell descriptor loader registration and lookup

Static PE/x86 follow-up to [the startup definition join](cell-start-definition-triple-publication-static-v1.md), using installed `SporeApp.exe` SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. No game execution or active provider observation. This identifies a concrete candidate loader registration, not a selected package or live player.

`E4C780..E4C7CE` allocates an eight-byte object, initializes its table to `01482FC0`, saves it at `[016AE040]+00`, calls `8DD7C0`, and calls the returned manager's virtual +44 with arguments `(1, object, 0)` in logical stack order. On allocation failure it supplies null; this slice has no manager null check. Conditional on the manager still having table `01437740`, +44 is `8E1440`; its nonnull-object/nonzero-flag path calls the object's virtual +2C first with zero output and zero count, then with a buffer and the returned count, and builds per-type registrations. The same table's +48 is `8DF310`, a type collection lookup used by the manager load path; see [manager registration and load route](cell-audio-factory-registration-static-v1.md). Object lifetime, successful allocation, call reachability and actual installed manager/table remain conditions.

The concrete table `01482FC0` has +1C `E4AD80`, +24 `E4AE20`, and +2C `E4AA80`. `E4AA80` traverses the linked descriptors rooted at `[016AE044]` using node +28. With null output it returns their count; otherwise it writes up to the supplied unsigned capacity the descriptor type word at each node +08. `E4A560..E4A5BA` stores descriptor arguments and, only if its flags argument low bit is set, links the descriptor to that list at its head. Therefore the actual type list and order depend on descriptor initialization and list state at registration. In particular, static schema registration for the `cell` descriptor at `016AE490`, type `DFAD9F51`, and the globally registered `globals` descriptor are described in [the definition trace](cell-player-start-definition-static-v1.md); their enumeration here is conditional on those particular initialized nodes being linked and still present when +2C is called. This enumeration alone does not establish that the kind-4 list descriptor is linked, a selected factory wins, or an on-disk resource was loaded.

`E4AD80` allocates a 20h-byte resource object, calls `8DD610`, installs table `01482FAC` and initializes object +1C to zero before returning it through the requested output. It can subsequently call the factory receiver's virtual +24, releasing the new object and returning failure if that call fails. This is the concrete factory candidate under the `01482FC0` table; it is not proof that the manager invokes that factory for a particular lookup. The resource table and factory table share contiguous image words: `01482FAC+38` and `01482FC0+24` both designate `E4AE20`, while only the actual receiver/table determines dispatch.

At `E4AE20`, the loader calls base `8DD470`; failure returns immediately. On success it traverses `[016AE044]`, comparing each node's +08 against the supplied type word and following +28 (`E4AE4A..E4AE61`). No matching descriptor returns success without the two descriptor fixups. On a match, the object obtained via the supplied interface virtual +0C for IID `0116D51E` is dereferenced at +14, receives the descriptor at +1C, then `E4ABC0` and `E4AAD0` are called in that order on the loaded data. The routine does not safely handle a null interface on this matched branch; valid pointers, proper interface identity and successful read are required. `8DD470` uses the passed resource's virtual interfaces and a stream read via virtual +30 and accepts an exact returned byte count (`8DD491..8DD54C`); stream, allocator, optional framing, flags and failure path remain dynamic. No claim of an identical raw stream provider follows from a matching key.

On the separate handle path `E82200`, ordinary `(ID, descriptor+08, 0)` requests first try manager +14 and then +0C on failure; preexisting cache/interface state and fallback can bypass or alter this route. If the +0C route selects the above registered factory for the corresponding type, successfully reads an object, and matches its descriptor, then the fixups run; these are chained conditions, not proof the branch is active. The `startCell` source ID, definition's structure ID and structure's kind-4 list reference require their own descriptor/type bindings and successful acquisitions. Provider order, type aliases, +14 results, cache hits, fallback, actual registration order, mounted database identities and live state remain unresolved. In particular neither this registration nor the separately inspected PatchData bytes establish PatchData precedence or a seed-1 player.

Use PE section mapping and instruction-aligned starts. The referenced registration/list state and dispatch results were not captured at runtime.
