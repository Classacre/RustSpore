# Jawhead state-4 start and mode: initial-image boundary

This is static file and conditional control-flow evidence; no live process, source actor pose, callback execution, or animated render was observed. The base PE SHA-256 is `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. A fresh Ghidra 12.1.4 `-noanalysis` import manually disassembled and decompiled `73EDF0` (exit 0; reported body ranges `73EDF0..73EF6C` and `73EF70..73F00E`). The separate project, script and logs are in `target/ghidra-jawhead-payload-v1/`; Ghidra reported import and library-resolution warnings. Its inferred signatures and cross-references are not complete. Exact instruction bytes for the direct-draw range were independently decoded from this PE in `target/ghidra-jawhead-state-v1/capstone-instructions.txt`.

## Initial bytes, not runtime values

The PE `.data` section begins at image VA `0150D000`, has raw size `0C4C00` and virtual size `212764`; its file-backed extent ends at `015D1C00`, and its virtual extent continues beyond `0162F883`. Therefore the payload at `0162F870..0162F883` lies entirely in the section's zero-filled virtual tail under normal PE loading. In particular the initial-image values for start at +0 and mode at +8 are zero **before any runtime initialization or writes**. This is an image-layout deduction, not a snapshot at draw time; relocation, constructor code, aliased writes, hooks and other threads may alter memory. It does not authorize silently substituting zero in a runtime rendering path.

Direct bytes at `73EEC8..73EF2A` show that the path requires context +4C to be nonzero (`73EECB..73EECD`) and chooses a candidate base from object +F0/+10 when its count equals context +4C, otherwise `0162C870`. It writes the chosen base to payload +10. With a nonempty descriptor vector, it additionally writes the base plus `48 * descriptor.first` to +10 and writes descriptor.second to +4; with an empty vector, it writes context +4C to +4. It then passes payload address `0162F870` to state setter index 4. This bounded instruction path contains no direct store to payload +0 or +8. Its branch guards, runtime count equality, pointer validity and actual invocation must be established separately. A pointer at +F0/+10 is only the selected runtime value under these conditions, not proof of a live actor pose.

## Bounded literal search

A complete raw-file scan for the little-endian bytes of the five addresses `0162F870`, `0162F874`, `0162F878`, `0162F87C`, and `0162F880` is saved as `target/ghidra-jawhead-payload-v1/literal-scan.json` with PE identity and sections. It found respectively 1, 2, 0, 0 and 2 occurrences; all mapped occurrences correspond to the address operands in the direct-draw instructions identified above. This is a literal-byte search only, not an instruction-aware whole-program xref or proof that no writers exist. Base-plus-offset accesses, dynamically computed addresses, relocation/indirection, overlapping instructions and externally written memory are outside its coverage. The absence of the literal mode address does not prove that mode remains zero.
