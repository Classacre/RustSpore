## Implementable production API sequence

1. `creature_data::parse(&decoded)`; require `exact`, `consumed == decoded.len()`, `validate_part_ranges()`, exactly ten parts. For indices 0 through 9 in original order, `part_view(index).raw_row.try_into::<&[u8;140]>()`; ensure typed `part_instance` equals little-endian `(low at row+136, scope at row+132)`. Never sort, deduplicate or substitute a graphic mesh's bounds.
2. Resolve each row's explicit part-PROP chain in order, preserving duplicate row occurrences. `classify_cell_part(&lists, Some(0))` takes `CellPartPropertyList` identifiers and parent links. The existing `examples/support/cell_classification_fixture.rs` demonstrates exact named PROP framing, sorted unique IDs, and the native Parent scope-zero substitution; `cell_capability_source_verify.rs` demonstrates checking every admitted candidate path for class agreement. Its loaders currently parse the TSV hash column but do not themselves check payload SHA; a new trust boundary must validate the manifest, every used raw payload and any chosen chain provenance. Reject missing, ambiguous, cyclic, malformed or conflicting-class paths; do not silently pick a package. For the smallest initial fixture, explicitly provide hash-bound class chains already checked by the existing corpus and state that this is an admission, not an independently resolved live provider.
3. Under a scoped/restored MXCSR `1F80`, call `build_cell_part(row, class, 0xA1C46DF2)` per row; convert each result to `CellCapabilityPart`. `build_cell_parts` is also available with ordered `[u8;140]` rows and parallel classes. The part builder and `derive_cell_capability_geometry` require caller-established SSE policy; do not assume the scalar API's own scoped guard covers earlier operations. `Context::from_control_word(0x027f)` supplies x87 policy. With empty center `[+0,+0,+0]`, call `derive_cell_capability_geometry`; apply `write_native_tail` to a 140-byte explicit initial snapshot. Preserve bytes it does not write, including unused index slots.
4. Parse the selected current Globals bytes with `cell_globals::parse`, read its five named getters +74/+78/+7C/+80/+90 into `CellCapabilityScalarGlobals`. Parse the pinned `curve-0.prop` with `prop::parse`, require exact consumed framing, unique named type `0030` / specifier `009C` Vector2 arrays and expected 18 arrays / 104 points, and bind each requested identifier to its source ordered point slice. Call `derive_cell_capability_scalars(&geometry.class_counts, globals, 0x5A38C4BA, CellCapabilityScalarContext { x87, sse: Policy::Mxcsr1f80 }, callback)`; the callback calls `sample_capability_curve` using supplied context. Unexpected or absent required identifiers should fail this selected-corpus fixture, rather than inventing a native provider/fallback. Apply its `write_native_tail` to the same 140-byte snapshot; assert queried ID and argument bits as well as all fields and preserved bytes. Checked API errors are fixture failures, not native error behavior.

A later separately prepared guarded `E51EC0` full zero-flag host could independently test the coupled operation and its side effects, but is outside this plan.

Add focused rejection cases for altered payload hash, duplicate exact package key, malformed/trailing CreatureData, missing/conflicting class chain, wrong curve type/identifier, changed source row order, unsupported old Globals, nonfinite input/overflow, mismatched reference context and retained-byte preservation. Use `#[ignore]` for install-dependent checks, architecture gate x86/x86_64 where required, cap file sizes/row counts, and keep original package paths out of tracked outputs. Do not integrate the synthetic kind-4 third word `7` into the admitted candidate's `40616200` scope; that is an unresolved runtime identity join. Model composition does not provide actor creation, cache lifetime, real resource resolution, or live contact.
