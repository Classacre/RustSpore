# Source feeding handoff: typed-state prerequisite

This audits the current signatures for an executable source-state fixture; no game, native executable, Cargo or GPU was run. The relevant interfaces are `cell_feeding_callback_boundary_v2::{EventRecord, SelectorOne, dispatch_boundary}`, `cell_feeding_route_v2::{PreHealDefinitionV2, PreHealAdmissionV2, FeedingSliceV2, pre_heal_slice_v2}`, and `cell_progression_v1`.

`dispatch_boundary` accepts an already-admitted record, explicit float-environment admission and a callback closure. It forwards a `SelectorOne` with raw `u32` actor and definition words, gate, raw event word and float; it neither resolves the actor nor snapshots external world state after callback. Its documentation explicitly requires caller-owned record lifetime and fresh downstream resolution. `pre_heal_slice_v2` accepts an integer health value, difficulty, a definition value snapshot and a public unit admission marker. It returns a health value and either a pending cleanup or a continuation amount. It has no actor identity, definition handle, callback completion proof or writeback target. The unit admission marker documents caller obligations; constructing it does not validate those obligations. The later routing and accounting helpers require separately admitted, fresh snapshots and do not provide intervening native effects.

The current types therefore cannot implement the requested handoff with **genuine typed actor/player/definition identities**. `EventRecord` and `SelectorOne` intentionally retain opaque words; they do not distinguish actor handles from definition handles or validate them. `PreHealDefinitionV2` contains values only, and the inspected Cell actor/event modules have no source actor pool, source player state, typed definition resolver, or post-callback snapshot that binds a resolved object to the selector words. The experimental `CellActor` and `CellFood` identities are unrelated prototype IDs and cannot supply these roles. Adding newtypes around the existing raw words alone would prevent accidental interchange but would not establish provenance, lifetime, generation, aliasing, or the source pool's semantics.

A meaningful standalone fixture needs these explicit inputs and checks before committing a heal:

1. An independently specified source actor-handle resolver that represents missing/stale resolution and returns the currently resolved actor identity and its +244 word; the exact generation/index contract must follow recovered pool behavior rather than invent one.
2. A fresh post-callback current-player handle/reference and a comparison with the resolved event actor after the callback; the callback can change the global player.
3. A source definition-handle resolver distinguishing the observed special/null case from unresolved or stale handles, with a stable resolved-object identity and the post-effects `hp_value`/`food_value` snapshot; missing must not silently become the native special case.
4. An explicit post-effect boundary snapshot containing signed difficulty and health read from that same actor, plus the caller's actual admission of relevant pointer lifetime and `E622F0` preservation. A typed fixture may model those assumptions but cannot prove native effects.
5. A writeback operation that revalidates the same actor identity and snapshot epoch before committing the returned health. If the actor/player/definition changed or the intervening calls are unmodelled, return a typed pending/stale result without mutation. A result of `ZeroFoodCleanupPending` remains pending, and progression is outside this handoff.

The fixture should exercise callback changing player or event actor, stale and unresolved actor/definition handles, nonplayer and zero gate, zero-food pending cleanup, positive heal and difficulty zero, effect-snapshot absence and rejected writeback after actor replacement. Assertions must distinguish the supplied fixture assumptions from the original event producer; no fixture should be presented as evidence that real contacts, callbacks, native identity or lifecycle were reproduced.

Until these missing source-state types and their resolver contract exist, no standalone handoff module can honestly check genuine identity or stale writeback using the existing APIs. This audit therefore does not create a module that merely wraps opaque words or treats construction of `PreHealAdmissionV2` as proof. The next concrete step is to recover and implement the actor-pool handle/resolve contract and definition identity/lifetime at `B71CC0`/`B71D00`/`E4CAA0`, then make fixture admissions explicit and bounded.
