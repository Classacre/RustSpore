# Conditional animation binding: selective executable check

This note checks the conditional cache/binding path, not a live Cell actor or animation. SporeApp.exe SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a` was decoded directly using PE RVA mapping and Capstone; the instruction bytes and disassembly are retained in `target/ghidra-binding-v1/capstone-instructions.txt`. Ghidra 12.1.4 also imported the same executable into a **separate** project with `-noanalysis`, manually disassembled entries `009A4430` and `009A3140`, created functions and completed decompilation. It reported bodies `009A4430..009A4537` and `009A3140..009A33B6`. Source script, logs, and project are retained in `target/ghidra-binding-v1/`. The original selective project was untouched. These are direct Ghidra results, not REA Evidence; the loader reported unresolved library links and import warnings. Manually seeded functions lack comprehensive analysis; pseudocode types, signatures, control flow and inferred values are not verified source semantics.

## Cache lookup and miss branch

At `009A4437..445B`, the caller-provided second input's +110 word, the first input, and an output location reach `009A37D0`. The test of AL branches on its returned byte. The hit branch loads the output slot and proceeds to `009A4526`. A zero return takes the miss branch, allocates size `38h` at `009A4473`, conditionally calls `0099EDC0`, and calls `009A1E00` at `009A44B2`. If that call's AL is zero and the candidate is nonzero, `009A44CA` calls `0099EDE0` and clears the candidate register. It then proceeds into the `009A44CF..4518` path even if that candidate was cleared: the path calls `009A4270` and conditionally replaces the returned location's word, including with zero. Exact map insertion, key ownership, allocation failure and concurrency semantics require `009A4270` and surrounding manager invariants; do not assume every builder failure creates a stable negative cache entry.

The miss branch's `009A44F8..4513` compares the candidate and existing location word; if unequal it conditionally calls `0099C650` on the incoming nonzero value, stores it, and conditionally calls `0099EDE0` on the previous value. At `009A4524..452A` the local nonzero candidate receives `0099EDE0` on exit; the raw pointer returned is not proof of lifetime outside the observed retain/release context. Equal-pointer branch avoids that replacement sequence. The Ghidra output corroborates this control-flow outline, while bytes establish the instruction order.

## Instance transition and binding choice

At `009A3154..3168`, comparison with the instance's existing first word skips the resource transition on equality; otherwise nonzero incoming resource +114 is incremented before storing the new word and invoking `0099CD90` on the nonzero old word. At `009A3172..318D` the analogous owner comparison skips work for equality; on change the nonzero incoming pointer reaches `A16FC0`, is stored at instance +4, and the old nonzero value reaches `9C4B50`.

At `009A3198..31BF`, two single-precision operations subtract a memory constant from resource +120, multiply by resource +11C, store a float, then load and store it as double at instance +B8. The retained source trace identifies the constant as 1.0; these instructions alone reference its address. A null resource takes a zero-value branch but `009A31C5` then reads resource +144, so null cannot be admitted as a complete safe call solely from this branch.

At `009A32E7..33B6`, a nonzero supplied binding branches to `009A3396`; when unequal to instance +8 it increments incoming +30, writes it, and conditionally releases the old value through `0099EDE0`. On zero supplied binding, the code reuses existing instance +8 or allocates a `38h` structure. On successful allocation, the visible instructions explicitly zero only offsets +00, +04, +08, +0C, +14, +1C, +20, +24 and +30; no claim is made about the other bytes. On allocation failure, the candidate is zero, and the path still reaches `009A1E00` at `009A3371` with the resulting instance +8 value, subject to the preceding pointer-comparison branch. That branch has owner-dependent setup and cleanup; the return byte from `009A1E00` is not visibly tested before the function's success return in this bounded range. Neither allocation failure nor a null-binding fallback is equivalent to a known successful binding.

## Implications and next boundary

A useful bounded implementation must distinguish lookup hit, miss, failed builder, location replacement, local release, supplied-binding self-assignment and null-binding fallback; it must state allocator, lookup and owner admissions. The observed continuation after a failed build matters when modeling cache effects, but the called container operations and full error domain remain separate evidence gates. The static path does not associate a particular Jawhead actor, creation, resource manager winner, ANIM, owner pointer, controller scheduling or mesh palette. No playback, native instruction execution or original-game frame was observed.
