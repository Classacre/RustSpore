# Cell zero-flag capability construction and source bridge

Static investigation of the pinned SporeApp.exe SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. This note reports source instructions and previously recorded bounded experiments, not a live actor or mounted-package selection. No original code was executed for this investigation.

## Miss and reduction

`E67A50` searches a cache keyed by the signed first word of the actor's +FC/+100/+104 triple. On the miss at `E67A96..E67AB6` it obtains the cache slot, calls `E83E60` with the whole triple and the cache count/rows, and calls `E51EC0` with count, row pointer, and final flag zero. In `E51EC0`, `E52493` compares that byte with zero, `E52498` stores +1288 without changing flags, and `E5249E` jumps to the epilogue only if nonzero. Thus this miss falls through to `E524A4..E5271F`; the skip-flag-one experiment alone does not cover the complete call. Allocation, insertion-before-population, failure, reentrancy, cache lifetime and provider effects are not modeled by a pure fixture.

The prefix zeroes thirteen counters at +1204, starts +1238/+123C/+1240 from mutable globals `016B4C08/0C/10`, and starts +1244 at positive zero. It consumes at most 64 produced rows and reduces their supplied classes, flags, transformed centers and radii. Its extent update is if/else-if; the radius uses ordered retained x87 operations and a committed binary32 candidate. See [capability cache](cell-capability-cache.md) for exact ordering and previous 28,398-case skip-flag original-byte evidence. `E6D7F0` later projects those four fields using actor data; neither this construction nor a model resource alone establishes actual live actor geometry.

Zero executes the scalar tail too. It writes +1248, +124C, +1250/+1251, +1254..+1270 and calls ordered property curves. It needs CellGlobals fields +74/+78/+7C/+80/+90, the mutable electric-recharge curve ID, source property lookup and declared x87/SSE context; branch-specific fields are consumed conditionally. `E837F0` queries property-list instance `C951EB63` with manager scope zero; [curve evidence](cell-capability-curves.md) reports two decoded installed PROP copies SHA-256 `c00576f276d3e3daa9f898985775ba13e173d66b492bc8e8fcf0b7b3b25a6462`. Its historical package-group labels are not asserted here as canonical keys. The separately measured 33,480 scalar original-byte cases used explicit Globals, source curves and contexts with checked provider callbacks; they do not prove a coupled runtime miss or runtime lookup winner.

## How rows are obtained

For triple word +04 equal to `476A98C7`, `E83E67..E83EE1` writes one flag-one, class-11 row, radius 1.0, origin from mutable globals `016B54E4..016B54EC`, nine matrix words from `016B5534..016B5554`, and repeats origin in its tail. Otherwise `E83EEA..E83F35` calls `4BC760`, reads the returned object's +98/+9C range as 140-byte rows, and bounds output to 64. Each source row's class comes from `E827A0` and its property-list inheritance; the row supplies bounds, scale, transform and copied words. `cell_part_geometry.rs` documents exact operations and `D9007204` creation-ID radius exception. A graphics model or animation rig is not required by this observed geometry reduction; no equivalence between its bounds and separately rendered mesh is established.

`4BC760` constructs local key words `(input[0], 0F43029A, input[2])` at `4BC771..4BC797`. At `4BC7A9..4BC7B5`, if `(input[2] >> 24) & 31 == 1`, it clears bits 24..28, retains input words 0 and 1, and recursively calls `4BC760` with that transformed triple (`4BC7BB..4BC820`). The rest of this alternate route performs further work and is not admitted as simple key substitution. Otherwise `4BC91D..4BC950` sends the constructed `0F43029A` key to the object returned by `67D7F0`, through its vtable slot +0C, and `4BC959` calls `4BD6C0` on a successful reference. The provider's lookup, package precedence, failure branches, object mutation and lifetime remain unresolved; a disk key must not be treated as the native winner.

The explicitly hash-bound list `9A391385:F9C3D770:00000000` has four raw IDs, including `A1C46DF2` and `E219E5D3`; its disk rows, runtime fixup, dynamic third word and selection are separate admissions ([selection note](cell-kind4-cache-selection-static-v1.md)). As an independent, useful installed candidate, [inspection evidence](cell-source-creature-inspection-v1.md) records `A1C46DF2:0F43029A:40616200`, decoded SHA-256 `6852040fa9a9376ed9025f4823e05024a22685a147e00e64d1b0f536b33e8cd8`. The third word `40616200` is an explicitly selected candidate scope, not a demonstrated value of the live selection's third word. With this word the above bit test is zero, so it follows the direct-provider branch, conditional on the other inputs being admitted. The repository's earlier all-package inventory and class/parent analysis cover 1,365 CreatureData copies and 46,418 raw rows, but those corpus counts do not establish a mounted winner or live player identity.

## Smallest source-bound next gate

Build a local, opt-in fixture with a caller-specified package, canonical key and SHA-256 for a CreatureData candidate, with stable-file admission; parse its first 64 exact rows. Explicitly supply and provenance-bind each row's classifier/property-parent result, the creation first word, empty-center globals, x87 control and MXCSR `1F80`. Compose `build_cell_parts` and `derive_cell_capability_geometry`, then compose `derive` from `cell_capability_scalar.rs` with independently bound current-format CellGlobals and PROP curve bytes, explicit mutable identifier and same contexts. Assert the output fields and query sequence, and compare the whole coupled flag-zero tail to a guarded original-byte run if one is separately authorized and prepared. Preserve initial bytes for unwritten tail/index/padding fields. Hash-bound list selection can be a preceding separately admitted fixture, but must not turn its synthetic third word into the candidate scope.

This gate bridges genuine installed bytes to bounded cache results, with explicit provider/class/global inputs. It is not sufficient for live Cell contact: runtime resource selection and inheritance, FP state, cache insertion and invalidation, actor transforms, pair generation and callbacks remain unproved. The Rust finite-input, bounded-class and error checks are safe API restrictions, not claimed native fallback or atomicity. The existing geometry and scalar tests are separately validated spans; composing their models without a coupled original comparison is model composition, not additional original execution evidence.
