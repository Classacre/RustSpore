# Cell progress segment selection and placement boundary

This is a read-only follow-up to [the value route](cell-ui-progress-value-route-v1.md), [the serialized graph](cell-ui-progress-graph-audit-v1.md), and [parent sizing](cell-ui-parent-sizing-audit-v1.md). It does not establish an active UI, original display size, resource winner, or live game state. The static source is the installed base executable SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`.

`E283A0..E28470` sums the five supplied unsigned words, retains its x87 reciprocal, separately multiplies the sum by the supplied binary32 progress, and stores that product as binary32. It uses `CVTSS2SI`, `CVTSI2SS`, a comparison, and a conditional decrement to form a floor-like bucket; if the bucket equals the sum it decrements it. It then iterates the supplied words, subtracting their bucket widths and their corresponding normalized widths, and divides the remainder by the selected word's normalized width. The routine returns a segment ordinal, within-segment bucket, and local fraction through caller pointers. Exact behavior depends on x87 precision/rounding, MXCSR, conversion edge cases and valid input; a zero sum, out-of-range input, or invalid array must not be treated as safe. The Cell constructor copies five source words all equal to two, so on an admitted ordinary finite 0..1 input this is a ten-bucket/five-segment partition, with an endpoint adjustment. Rounding near boundaries needs an original-instruction comparison before exact implementation.

At `E29BD3..E29C20` a change in the float argument causes the routine to call `E283A0` and look up ID `051B54C0 + segment ordinal`. Successful lookup of that segment and `051B5168` is conditional. `E29C53..E29C73` computes cursor x as `segment.left + (segment.right - segment.left) * local_fraction`, using ordered SSE scalar operations; it reads cursor y from the other control's rectangle at `E29C7F`. Later animation calls affect the result, so this coordinate alone is not a completed frame or visible cursor. `E296F0..E29802` also conditionally reads these controls' virtual +38 rectangles during initialization and calls `E289B0`; those rectangles are runtime interface results, not the raw inverted serialized rectangles.

The existing experimental Cell simulation's mass-derived `CellWorld::progress()` is not proven to equal the source `P+1C` input. Even with an admitted source value, choosing an installed layout or atlas, slot occupancy and state, final parent matrix, visibility, and animation phase would still be assumptions. Consequently the current explicit single-segment preview should not automatically switch segments or position a cursor from prototype progress.

## Explicit-input model

`cell_ui_progress_selection_v1` models the five fixed widths with a caller-supplied x87 arithmetic context and finite progress in 0..1. It models cursor x separately from a supplied rectangle and fraction under explicit MXCSR `1F80`. The bounded nonnegative bucket range allows the native SSE conversion/conditional-decrement sequence to be expressed as floor; x87 operations retain the reciprocal and commit each intermediate remainder to binary32. Three focused tests passed via `tools\build.bat test -p spore-core cell_ui_progress_selection_v1`: representative interiors and endpoints, adjacent values around each segment boundary, unsafe-input rejection, and supplied cursor arithmetic. These tests do not compare original instructions, validate native FP status or establish live control state, package selection, animation or screen placement. The model is not connected to the experimental frontend.

The inputs were zero, the smallest positive subnormal, the nearest binary32 representations of 0.1 through 0.9 and their immediate neighbors, the predecessor of 1.0, and 1.0. Host and adapter exited zero, and both stderr files were empty. The host checked output canaries, x87 stack top/stack-fault status and MXCSR control bits.
