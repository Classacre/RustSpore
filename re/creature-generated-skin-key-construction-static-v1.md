# Creature query keys and constructed edge membership

Static x86 trace of installed `SporeApp.exe`, SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. It extends [the accumulation trace](creature-generated-skin-accumulation-static-v1.md). No original game or copied instruction was executed for this note.

## A concrete array relationship

On the nonempty, successful `4CB400` path the receiver's `+08` object supplies `+98/+9C` 0x8C-byte rows. The receiver's `+40` vector contains 0x34-byte endpoint records, and `+54` contains eight-byte edge records. At `4CBF96..4CC004`, the routine iterates each constructed edge ordinal `i` in increasing order. It reads both endpoint indices from `+54[i]`, calculates `+40 + 0x34*endpoint + 0x0C`, and calls `421F30` with the dword `i` for each endpoint, in first-then-second order. `421F30`'s capacity-available path appends that dword to the pointed vector; the grow path calls `427D60` and requires successful allocation. Thus, conditional on valid arrays and successful appends, each +40 member is an ordinal into the constructed +54 edge array. A self-edge appends the same ordinal twice; parallel edges remain distinct. This does not identify any member as a CreatureData row or palette ID.

The edge array is row-derived but is not generally an identity map. `4CB9E3..4CB9F2` writes consecutive endpoint indices for the leading class-5 loop. `4CBB1D..4CBB61` writes the class-3 loop's first endpoint from either the referenced parent row's signed +02 word or this row's signed +02 minus one, selected by +08 mask 2, and its second from this row's signed +02. `4CBC82..4CBD1E` handles remaining rows with additional class-5-count and parent-dependent choices. `4CBE63..4CBE83` writes additional flag-selected edges after the original row count. Bounds, signed parent/index validity, exact flag/class gates, ordering and allocation must be validated before attempting a safe full reconstruction. These statements summarize retained `4CB400` decompilation and the cited instruction stores; they do not establish every special-case invariant.

## Lane key provenance on one conditional producer path

`413D70` takes an intermediate object as its stack argument. It reads that object's +08 -> +98/+9C rows, checks for at least one row with +08 mask 1, and then populates a separate temporary builder. Its leading class-5 row loop passes a position and sign-extended row +00 to `4FD2E0`; for each subsequent row, `414041..414062` passes the **previous** row's sign-extended +02 OR `80000000` as the fourth data field to `4FD360`. The routine then updates the previous +02 and node index. The class-3 route invokes `412890` at `4141A0`; retained pseudocode shows additional builder-node keys from row-derived values with the high bit set and clear keys from a supplied row +00 value. Its geometry, parent and branch assumptions remain necessary; do not generalize these examples to every key or every row.

`4FD2E0` appends a 0x18-byte builder node, with the supplied key as its +14 word. `4FD360` appends a 0x10-byte builder segment with its supplied key at +0C. Both depend on their vector append helpers and allocation. `4141CB..4141F6` calls `4FDA40` on this builder, supplying the *same intermediate argument's* +38 pointer as the query receiver. `4FDA8A..4FDABB` passes each builder node's +14 key to `4F9100`; `4FDB94..4FDBD0` forwards each segment's +0C key through `4FD3C0`, whose sampled interior records call `4F9100` with that supplied segment key. `4F9100` allocates/extends 0x80-byte, four-lane records and passes the word to `4F8930`; at `4F8990..4F8996`, the latter writes it to lane +70. `4F8A30` copies the lane +70 word at `4F8AC2..4F8AD2` when repacking. `4F8AE0` later appends that word unchanged on its gated positive-weight path. These are direct producer/consumer relationships under the described call, valid storage, helper, floating-point and allocation conditions; they are not runtime observations.

`4CC491..4CC4B4` separately passes its receiver's +38 to `52B700`, which supplies that pointer as `4F9C30` receiver. Consequently, **if** `413D70`'s intermediate argument and `4CC060`'s receiver are the same object and no intervening replacement/rebuild mutates +38, this establishes a candidate query-object join. `4143C0` and `414410` call `413D70`; this trace does not establish that either path ran for the currently edited creature or establish the necessary same-object and timing conditions. Other constructors/providers may exist.

The 0x8C layout resembles the serialized CreatureData part row, and the source parser exposes +00, +02, +04 and +0B. The runtime row pointer's origin, exact backing bytes and lifecycle were not joined to a selected payload in this trace. The separate canonical animation constructor `9CBFA0` and its conditional finalized +21C palette result, described in [the rig analysis](anim-rig-native.md), do not by themselves identify this query builder, the row-derived +00/+02 values, or the 52B700 accumulator index with a finalized palette entry. Numeric equality is insufficient. A complete bridge needs the runtime row loader/identity and same-object lifecycle, all `412890`/builder and grid paths, remap provenance, and a demonstrated output-to-palette consumer. No new source-row or palette implementation is justified by this conditional trace alone.
