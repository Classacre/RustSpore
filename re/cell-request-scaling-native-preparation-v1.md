# Prepared original scaling host

After source and linked-host review, the local comparison ran 7,680 cases.
All 7,656 supported cases matched the original instructions exactly on updated
state and stored binary32 bits. The remaining 24 round-down zero-sign cases
were recorded separately as intentional model exclusions. The result report
`target/cell-request-scaling-native-result-v1/report.json` has SHA-256
`475c5459ccf3090637d4892050ed4d4873696577c924039e31d60464a0909034`.
Ten source, host, tool and executable hashes were checked before and after;
toolchain libraries and the live game's control word were not pinned. The
model uses local hardware x87 operations, so this is not independent software
arithmetic or validation of live actor admission.

The generator was subsequently changed to keep decoded disassembly only under
`target/`. A fresh structural verification generated byte-identical host C
(SHA-256 `02ab767f8eb82386b9ea30c5fa713d51767ce517e525158d3cc71b44e1a0f4eb`)
without altering the retained comparison artifacts.

`tools/cell_request_scaling_native_prepare_v1.py` reads only the SHA-256 pinned retail image (`17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`) and writes generated source and an exact disassembly manifest into a fresh ignored `target/` directory. The preparer verifies the three source-slice SHA-256 hashes, complete decoding, control-flow destinations, relevant stack and absolute operands, the RNG global address, and the two constant bit patterns. Decoded instructions are recorded only in the ignored target manifest. The prepared local files under `target/cell-request-scaling-native-prep-v2/` are not a native execution result.

The proposed 32-bit MSVC host reserves the original 64 KiB address ranges, failing on any collision. It copies source instructions to their original virtual addresses and routes execution after the original FSTP at `E6D166` to a host label. For each input it saves the host x87 environment, initializes an empty x87 stack with the requested masked control word, saves ESP, reserves a synthetic source stack, supplies the f32 sum at `[esp+10h]`, and reads the f32 result at `[esp+18h]`. It restores ESP and the host x87 environment. The RNG global at `01602760` is populated per request; zero state is rejected, so RDTSC is not entered. Fixed-address pages are private to the host process. The source machine code and constants remain in the ignored output, not in tracked source.

Protocol: each binary input row is three little-endian u32s: nonzero state, finite nonnegative binary32 sum bits (positive zero admitted, negative zero rejected), and x87 control word. Valid control words have all exceptions masked, PC53 or PC64, and any of the four rounding modes. Output is two little-endian u32s: advanced state and **raw** f32 draw bits. x87 status flags and retail control word are not established. The host is single-threaded and the synthetic stack and global do not reproduce live game concurrency.

Check the executable SHA and input/output lengths. Native build, execution, and model comparisons have not been performed.

For future comparison, construct a reproducible corpus over both precision modes and all four rounding modes, with nonzero states chosen using the inverse RNG multiplier to reach signed boundaries and endpoints, plus deterministic random states. Include zero, minimum subnormal, normal, large finite and sum-boundary f32 values. Compare each raw output word and advanced state with an independently implemented scaling adapter; retain input and output hashes, failures, compiler identity and manifest. Test the state `0x80000000` with round-down explicitly: the current model rejects the zero-sign case, so record the host's raw bits separately and do not count it as a model match. Exercise all rounding modes and sums for that state, including zero sum. Any additional model rejection is reported separately rather than silently excluded. Do not claim success until the linked host is reviewed and the actual comparison is complete.

The prepared comparison adapter is `crates/spore-core/examples/cell_request_scaling_native_compare_v1.rs`, using one predicate-passing, part-code-one row. It verifies the admitted candidate and exact sum bits before returning the public model draw. Its output records are `(status, state, draw_bits)` as three little-endian u32 values; status 1 is the model's transactional zero-sign rejection and its state remains unchanged. Any other model error terminates the comparison.

`tools/cell_request_scaling_native_run_v1.py` constructs 7,680 deterministic cases: eight PC/rounding combinations, 80 distinct nonzero states, and 12 finite sums covering positive zero, subnormal/normal boundaries, values around one, and maximum finite binary32. Twenty-four exact-cancellation round-down cases are explicitly recorded as model rejections, including the host's raw draw bits; they are not model matches. All other cases compare updated state and raw draw bits exactly. Requests, both outputs, stderr, executable hashes, mismatches, and a report are saved in a new ignored target directory. The runner does not establish a live game control word and an exact comparison is evidence only for its bounded corpus. The model's x87 primitives execute on local hardware, so this is not an independent software arithmetic implementation.
