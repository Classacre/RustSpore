# Creature-stage source scene and UI integration gap

The experimental Creature scene in `creature_game.rs` creates its terrain procedurally and constructs Bevy HUD elements; source Creature selection changes the inspected player art. Existing source UI renderers and SPUI parsing can draw controlled supplied layouts, but this does not establish a Creature-stage layout, active provider, dynamic control values or placement. Existing BlockData analysis explicitly does not identify those samples as terrain. No original landscape geometry, materials, environmental effects, or world lifecycle is bound to this scene.

A fresh selective Ghidra 12.1.4 `-noanalysis` project is retained at `target/ghidra-creature-ui-v1`, imported from the executable whose SHA-256 is `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`; this is static evidence, with loader warnings and unresolved links. PE instruction decoding corroborates `D3BD40..D3BD7D`: it constructs an object through `D3B980` and registers it under literal `Game_Creature` with ID `01654C01` via a caller virtual +20. This establishes a conditional stage registration, not an environment or HUD resource binding.

An initially tempting global-UI path is not established as Creature UI: at `DE5863..DE5881` it allocates the object labelled `UI/GGE/GlobalUI`, and `DE5890..DE58C7` hashes the dynamic string at `016A1D04` then passes a key to that object's virtual +8 at `DE58BA..DE58C7`. Allocation failure leaves a null object followed by an unguarded dereference, so this route requires a valid allocation. Static initializer `136BAE0..136BAEA` initializes that string from the UTF-16 literal `GlobalUIGGE-9` at `0147DF64`. This provides a concrete distinct GGE UI candidate, not evidence that it is the Creature HUD. The decompiler body `DE56D0..DE5A2A` and constructor `E03730..E03799` are recorded in the project; manually seeded decompilation is not proof of full initialization or runtime dispatch.

Next actionable trace: follow `Game_Creature` object's initialization through the installed vtable `0147B740` and its stage-entry calls to find actual world/environment resource references and a HUD layout loader; then join a unique canonical package key to the layout or world, implement the required provider/order and rendering bindings, and expose any unproven state as an explicit inspection admission. For UI, each chosen SPUI needs its drawable/image references, fonts, clipping and viewport layout, plus evidence for any state-driven controls. For terrain, require a source world/planet resource, geometry and material producers, coordinate/camera transformations and lifetime. Until those are known, placing unrelated SPUI or a guessed terrain texture in the scene would not be a source-grounded improvement. No application code was changed for this investigation.

## Conditional Creature HUD candidate and minimap holder

A second fresh selective project `target/ghidra-creature-entry-v1` decompiled entry-related functions; PE bytes anchor the following callsites. In the `D43DE0`-seeded continuation, the branch at `D44842..D44868` skips the following sequence when ESI equals `00DBDBA1`; otherwise it calls `D391D0` with a boolean indicating equality with `01654C08`, then calls `D3C400`. `D391D0` calls `D2CBB0` only when the Creature object's +68 owner was initially null and construction reaches the call; if it is already populated the prior UI state is reused. On a successful allocation, `D2CCCD..D2CCFA` constructs `E03730`, stores it at owner +58, and calls its virtual +8 with the three words at `015839A0`: instance `5ED10964`, requested type `0510A95B`, scope `40464100`. Allocation failure produces zero before an unguarded dereference, so valid allocation is a prerequisite. The constructed vtable +8 is `E032A0`, which passes the supplied key to `811E30` at `E0334E..E0335A`, conditional on its internal object being nonzero. The previously audited `80FA70` may rewrite the scope to `40464200`; the registered type mapping may associate `0510A95B` with serialized SPUI `250FE9A2`. Neither remapping, provider success nor selected package is guaranteed.

An independent flag-driven index read found canonical `5ED10964:250FE9A2:40464200` in PatchData ordinal 24419 and Spore_Graphics ordinal 23492, each decoded size 151999 and compression `FFFF`. PatchData package SHA-256 is `cadbff237076b441e6981503f80538705aefa5863bb4c8d1b869f9db98d1adff`, decoded SPUI SHA-256 `16b7c334373f58c9bf7933ce88dc7ceb18a7fd4b9a73bde23377ceb256459f2c`; Spore_Graphics package SHA-256 is `e01bb86d8ddf02c56d52394b4e1db7181c1e1ebe1878bf6fb72c4ee523fcedd1`, decoded SPUI SHA-256 `8f902bc04b4e4dae4a10f0a76c9e07c3019e2bcbb451bc088afac186afee9724`. Legacy census archive group words are metadata, not canonical scope. The 82-package, 748-SPUI decoded census `target/source-ui/creature-control-census-v1.json` found several other SPUIs carrying the same control IDs, so control co-occurrence alone is not a unique association.

`D3C400` accesses the owner +68/+58, calls `810310` for control `0190722E`, derives dimensions from its virtual +38 rectangle, then constructs an object labelled `UI/CRG_Minimap` at `D3C486..D3C4F1` and binds its interface through that control's virtual +D8 at `D3C530..D3C542`. This conditional path requires valid owner, control, rectangle and allocation results. The candidate SPUI graph `target/source-ui/creature-ui-graph-audit-v1.json` identifies `0190722E` object 965, named `Minimap holder`, with serialized root path 969 -> 968 -> 966 -> 965 in both copies; control `0562A0F7` is object 968. The holder's own reachable closure has only itself and one layout object; its live minimap content is supplied by the separately constructed dynamic object, not an authored texture in that closure. Its parent control has many image objects referencing PNG `FE081DAA:2F7D0004:31A44893` in the serialized resource table. Those references identify an atlas candidate, not native draw order, decoded atlas winner, runtime widget state or proof the holder displays the atlas.

A truthful controlled compositing implementation needs explicit selected package and hash-bound decoded layout/atlas, validated image-reference closure, source drawable-state and clipping selection, viewport/layout calculation, and caller-supplied dynamic content; the existing Cell UI fixture renderer accepts manually selected rectangles and synthetic state, not a complete SPUI runtime. The candidate association is stronger than co-occurrence alone but does not establish an actual rendered Creature frame, provider precedence, or a complete HUD.

A specific static frame lead within the parent closure is window 963 -> drawable 886 (`B03C196F`, mode 2) -> slot-zero image 885 -> resource ordinal 90 -> PNG `FE081DAA:2F7D0004:31A44893`. The image and window link are serialized graph facts; which slot is active and the final viewport rectangle remain runtime/layout inputs. Flag-driven index inspection found this PNG in the explicit Spore_Graphics copy at ordinal 10259, uncompressed 380813 bytes, SHA-256 `e39080bbd54cf228a138b1d3d566926b80601f9e19cb199adac8f4641f48f3c1`, IHDR 512x1024; it was absent from the explicitly checked PatchData index. Other mounted/provider sources remain unexamined as winners. The existing D3D fixture is hardwired to the Cell layout, a different atlas, a 768x768 target and explicitly supplied rectangles; it is not an available automatic Creature UI compositor. A source-bound frame preview must first implement/admit the selected state, transform and clipping and then a Bevy-compatible texture/overlay handoff; rendering the PNG or an arbitrary rectangle would not reconstruct the minimap.

`D391D0` caches its owner pointer before calling `D2CBB0`; `D3C400` separately reloads global `0169F274` and follows its +68/+58. Connecting the loaded layout to that later control lookup therefore requires the same global/owner identity to persist, plus callback and lifetime stability. The decoded sequence does not prove those conditions, nor that either call completes successfully.

The window-963 drawable's mode-2 properties include four serialized slice-margin words `3EE66666`, `3E800000`, `3F0CCCCD`, `3F400000`. A single Bevy stretched image would not preserve that operation. The next viable controlled overlay is a hash-bound graph/atlas admission with explicit viewport, destination, state and clipping, applying the existing source mode-2 slice routine to produce validated ordered quads and mapping those into Bevy; this still would not implement the dynamic minimap or entire HUD. No such compositor was added in this pass.
