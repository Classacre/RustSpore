# Conditional Cell palette producer and pointer lifetime

Static analysis only. The base executable SHA-256 is `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. PE-mapped direct x86 bytes for `9C6E40`, `744AA0`, `73B7C0` and `73AB00` are retained in `target/ghidra-jawhead-payload-v1/producer-instructions.txt`; earlier retained source dossiers and their scope are indexed in `anim-palette-native.md` and `cell-animation-owner-palette-draw-static-v1.md`. ## Buffer producer to LOD

At `A047D6..A04804`, conditional on a nonzero CID +2C0, `A04670` supplies a pointer based on request object +190 +68 to `9C6E40`. That pointer is an input to the producer, not by itself the table pointer ultimately stored in the LOD. In the active matrix branch `9C7A72..9C7A99`, `9C6E40` calls `9C6B10` with the CMID vector at +10, then loads that vector's first pointer and saves it. It writes records in 48-byte steps on the ensuing loop and, at `9C7E0C..9C7E38`, passes that saved pointer, a count derived from CMID +10/+14, and CMID +8 to virtual +98 on CMID +4. On a different branch at `9C7E47..9C7E5D`, it passes a null pointer instead. Entry/branch and object-state conditions remain material; this is not a universal update.

Under the established standard-world vtable identity and a valid nonnull model argument, `744AA0` forwards that pointer and count to `73B7C0` for at most four successive nonnull LOD slots, stopping at the first null slot. A null first argument leaves the computed base null before the subsequent dereference at +B4; it is not a safely admitted model. At `73B7C0..73B7F1`, the setter clamps the signed count to the signed first-group count when a group exists, increments revision +90/+94 with carry, and writes the supplied pointer at LOD +10. It performs no matrix copy or pointer retention in that instruction body. Separately, under the earlier proven conditional graphics association, `73AB00` stores the LOD object at graphics +F0, with a reference increment on a changed nonnull new object and release logic for an old one. The reference to the LOD object is not evidence that its raw +10 matrix allocation is independently retained. `73AB3D..73AB49` also dereferences its supplied LOD after the replacement branch, so an all-null invocation is not safely modeled merely because the increment branch tests for null.

## Lifetime boundary

At `9C6B10..9C6B93`, the CMID vector operation uses an unsigned comparison of requested count with its current 48-byte element count; the vector span and arithmetic must be valid caller state; growth calls `9C68E0`, and the other branch calls `FB3680` with a derived position. The current pointer must therefore be read **after** that operation, as the observed caller does; changes or later vector resize/destruction may invalidate a prior pointer. The checked instructions do not prove that a particular growth call reallocated, when the vector is destroyed, whether the LOD pointer is cleared before that event, or the synchronization between update and draw. No broad lifetime guarantee follows from pointer assignment or LOD reference counting. The direct draw only picks LOD +10 when its stored +0C count matches a nonzero draw-context +4C; otherwise it chooses `0162C870`, before descriptor offset and state publication.
