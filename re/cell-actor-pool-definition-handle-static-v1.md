# Cell actor-pool and definition-handle static boundary

Static Capstone x86 disassembly of installed `SporeApp.exe` SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`; preferred base `0x400000`. No original program, GPU or Cargo execution. The routines below are generic pool/helper code; Cell connections are the cited call sites. This is not a proof of live actor reachability or thread synchronization.

## Pool layout and allocation

`B71B70..B71BCA` initializes the pool with backing pointer +00, free-list head +04 set to `FFFFFFFF`, counter +08 initialized from a global counter shifted left eight bits, live count +0C and initialized-slot count +10 set to zero, stride +14 and capacity +18 from arguments. Allocation is performed before those stores; allocation failure handling is not established here.

`B71C50..B71CB0` returns zero if live count equals initialized-slot count and also equals capacity. Otherwise, if live equals initialized count it selects the next never-used index (the previous live count) and increments +10; otherwise it takes the slot index from +04 and changes +04 to the dword stored at that slot. It increments the pool's +08 counter, increments live count, forms the returned word as `(counter << 16) | index` in 32-bit arithmetic, zeros the entire stride, and writes that word into the slot's first dword. The `<<16` retains only the low 16 bits of the counter in the resulting handle; index is ORed without an explicit mask. Exhaustion or wrap conditions, supported maximum index, memory allocation validity, and the behavior of the free-list invariants under misuse remain unproven. It is unsafe to assume this yields globally unique or never-reused handles indefinitely.

At `E74AF8..E74B14`, Cell takes the pool at `[016B4BE4]+1C`, calls `B71C50`, then passes the returned word to `B71D00`. The inspected path does not check allocation returned zero before that fast lookup; do not emulate a dereference on exhaustion in a safe model.

## Two different lookups and removal

`B71CC0..B71CEF` returns null for handle zero, extracts `handle & FFFF`, compares that index to pool +10 using signed `JG`, computes `base + stride * index`, and returns the slot only if its first dword exactly equals the original full handle. The observed branch rejects `index > +10`, **not** `index >= +10`; an index equal to initialized count reaches a memory read. A safe implementation should independently require an in-bounds initialized slot before checking the full word, and label that as a defensive restriction rather than a verbatim native branch. This routine does not by itself prove concurrent lifetime or guard against counter wrap, and raw-address arithmetic can overflow.

`B71D00..B71D0F` is materially different: it masks the argument to its low 16 bits and returns `base + stride * index` without checking zero, +10, capacity, or the full stored word. Calls to this function alone are not evidence of a successful or fresh handle resolution. Its callers must establish the preconditions separately; an actor ID being nonzero is not sufficient.

`B71D50..B71D71` also takes the low 16 bits without verification, stores the prior free-list head in the first dword of the selected slot, decrements live count and makes that index the new free-list head. The old full handle normally ceases to match at release; subsequent reuse writes a new counter/index word, but the unchecked routine, sentinel values, counter wrap and malformed or duplicate frees preclude a blanket stale-handle guarantee. In the Cell cleanup path, `E78242..E7824C` passes the actor word in EBP to this pool removal after other cleanup; the full cleanup ordering and reentrancy remain outside this trace. `B71C00` resets live count, initialized count and free-list head but does not itself clear the backing allocation or increment its counter.

## Definition object and pointer lifetime

`E4CAA0` is a tail jump to `E823D0`. The first stack argument is dereferenced as a pointer to a definition-handle object; the second receives that same pointer, and its +0C count is incremented. If object +08 is zero, `E822F0` is called to attempt loading. On a nonzero +08, the code calls its virtual +0C with interface ID `02269ED1`, then reads the returned interface pointer at +14. This is not an integer lookup by a Cell definition ID. The returned pointer, object identity and lifetime depend on that handle, resource provider and caller-owned output wrapper. `E823D0` does not verify that the input handle pointer or returned interface pointer is valid; the displayed no-object branch at `E82405..E82407` also contains an effective read through address `0x14`, so it cannot be treated as a reliable safe missing-value return.

In `E822F0`, the handle's +00 and +04 words and +08 object slot are supplied to `E82200`; that helper rejects first word 0 or `FFFFFFFF`, builds a key using first word and the +08 word of the object at handle +04, tries resource-manager `67D7F0` virtual +14 then virtual +0C, and may invoke the handle-related object's +20 callback after obtaining interface `02269ED1`. On failure `E822F0` invokes the fallback path `E82170`; that function constructs a key containing `7A638526` and a word at the referenced object's +08 and calls manager virtual +1C. These paths do not establish overlay order, concrete selected key or identity equivalence after reload. The `E823D0` caller's pointer/handle and output wrapper must remain valid, and callback/resource-load side effects are not covered by a plain value snapshot.

For the feeding path, `E7D0D2..E7D0E5` compares the incoming definition-handle word to global `[016B4BF4]`; equality bypasses `E4CAA0`, otherwise it calls it with that handle and a local wrapper. This special comparison is not equivalent to a failed resource lookup. Before healing, the same function calls `B71D00` for the global player handle (`E7D0A0..E7D0C0`), so it relies on caller/lifetime invariants that this fast lookup does not check.

A safe source handoff can use separate actor and definition handle types, but must first preserve the exact 32-bit actor word and pool identity, validate initialized-slot bounds and full-word equality at each required boundary, and separately validate definition pointer identity, lifetime and post-callback/post-effect snapshots. If a revalidation, allocation, interface, or provider invariant is unestablished, return pending/error rather than reproducing unsafe access or inventing a special-null definition. These safe checks restrict behavior; they do not claim retail execution performed them.
