# Cell source health: update-path admission audit

This is a code audit of the current checkout and [the source-health proposal](cell-source-health-integration-proposal-v1.md). It does not run the application or establish original runtime behavior.

## What is selectable today

`cell_game.rs::run` accepts paired `--source-cell-install`/`--source-cell-id` or `--source-creature-install`/`--source-creature-instance` options. They are mutually exclusive inspection-art choices, not source simulation modes. The Cell choice loads a `SourceCellLibrary` asset (or a separate kind-0 inspection asset), then keeps mesh, skin, sampler and inspection transform in `SourcePlayer`; `SourceKind` distinguishes the two art paths. The selected Cell definition identity and the library are not retained in the `Game` resource. `configured_world` independently constructs the same prototype `CellWorld` whether either source artwork is selected. The label in `setup` explicitly says static PBR inspection art and experimental gameplay.

`Game` owns the prototype `CellWorld`; Bevy schedules `drive`, `sync_scene`, `update_hud`, and `capture` in that order. `drive` unconditionally calls `game.world.advance(dt, keyboard_input(&keys))` under its normal unpaused/time gates, including both source-art choices, and discards its `StepReport`. `SourceKind` is used for inspection/save behavior, not to select an actor-pool or source event implementation. Restart replaces or resets the prototype world; source Creature inspection blocks F5/F9, while source Cell inspection still uses the prototype snapshot subject to its authored-creation guard. HUD and result logging read the prototype float health and mass-derived progress.

The prototype's `CellActor` has a generated `u32` id, 2D position, float health/mass and diet. `CellFood` carries only prototype id, position, plant/meat enum and float mass. `CellWorld::step` detects its own geometry, applies prototype bite and damage, and `feed` mutates growth/removes food before reporting `CellEvent::Ate`. That event contains prototype actor/food ids, kind and mass. It is therefore both too late to serve as a pre-mutation source event and lacks the source pool handle, actor +108 definition handle, current player reference, case-10/selector admission, raw dispatch word, difficulty, callback results and fresh definition snapshots. Retaining `StepReport` alone cannot fill these gaps.

The core modules `cell_feeding_route_v2`, `cell_feeding_callback_boundary_v2`, `cell_feeding_contact_arbitration_e59b40_v1`, and `cell_progression_v1` expose bounded source slices and explicit admission types, but no Bevy Cell update code calls them. Their presence is evidence of modelled fragments, not a source actor/event producer. The inspection asset's definition lookup is not a demonstrated runtime overlay resolver, and visual source identity is not proof of an edible actor's definition or of a player assignment.

## Smallest safe integration boundary

A separate, explicitly named source-simulation selection would be needed; do not repurpose `SourceKind` or existing source-art flags. Its state must be distinct from `CellWorld` and own generation-checked source actor handles, current player handle, signed +244 health, resolved definition handles with native identity/lifetime, difficulty and ordered pending event records. A constructor must either receive explicitly admitted fixture state for a headless engineering test or follow the traced actor creation/player assignment and actual resource resolution; it must not infer a native actor from the displayed mesh.

A future source update system should run after its own ordered contact/event creation and callback boundary, then re-resolve the event actor, current player and definition before invoking `pre_heal_slice_v2` with a fresh post-effects snapshot. Keep routing and progress accounting pending until their intervening effects and snapshots are available. A stale handle, unknown event, unavailable difficulty, unmodelled callback/effect, or unsupported definition must result in an explicit pending/unsupported state rather than committing a guessed change. Source HUD should only read this independent state once such a mode exists; current prototype HUD remains labelled as prototype.

A useful first engineering test can inject a clearly labelled admitted fixture directly at the post-callback boundary and assert health writeback, identity re-resolution, pending zero-food and stale-handle behavior; it tests the handoff only. A source-backed acceptance gate additionally needs an asset-backed actor pool and ordered producer/contact/callback chain that actually creates a valid selector-1 record during the update. No such producer, source actor pool, or verified difficulty source is present in the current Cell Bevy path. Consequently there is no honest current input with which to attach the source healing slice to `drive`; wiring it to prototype food or damage would create an unsupported association.
