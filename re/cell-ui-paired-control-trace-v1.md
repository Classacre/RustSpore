# Cell UI paired controls: geometric trace and follow-up

This is a bounded static observation of the installed base `SporeApp.exe`, SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. It does not establish an active screen, package selection, control visibility, gameplay value, UI event, or original frame. The source candidates and guarded resource-type association are in [the Cell UI audit](cell-ui-candidate-audit-v1.md) and [registry audit](cell-ui-registry-audit-v1.md).

The retained Ghidra dossier for `E54150`, `target/rea/20261028-source-runtime-v6/36-analyze_function.json`, has SHA-256 `48f4166d1080b4da2114f622e5cf9cf9fc9f9c435b79d77505957bfa9e3ed60e`. Its decompilation shows Cell initialization requesting `GlobalUICell-3`, looking up paired IDs `05AF4BF0`/`05AF4AF0` and `05AF4BF1`/`05AF4AF1`, and passing each pair and mode 1 to `E53F90`. It then retrieves `05AF4BF2` and `05AF4AF2` and performs a related sequence of virtual rectangle access and writes. All six IDs occur in both candidate SPUI payloads. The meaning of the IDs is unresolved; do not identify them as health, DNA, progress or any other gameplay field.

A read-only Capstone decode of the installed bytes at `E53F90..E54084` shows calls to each object's virtual +38, subtraction of the second result's first float from its third to obtain a horizontal span, a call to `806B40` with that object and zero arguments, a second span subtraction, and mode dispatch. The decoded mode-2 branch uses the resulting span difference in virtual +6C and +70 calls. This is a geometric relationship and a bounded branch observation, not a complete decompilation of every mode, a proven runtime vtable identity, or evidence of a live layout. The mode-1 calls observed in `E54150` do not establish the mode-2 branch's execution.

After the pair setup, the `E54150` decompilation shows allocation under `Simulator/Cell/UI`, constructor `E00B60`, and a retained pointer at Cell-global +98, followed by `E020B0`. It separately shows constructor `E28480` receiving the layout pointer at +90 and `DAT_01485ED0`, retaining the result at +94, and calling `E296F0`. It also shows a root lookup for `FFFFFFFF` followed by virtual +104 calls. Inferred types, receiver provenance, indirect targets and whether any of these calls execute remain unresolved; the +104 calls cannot be equated with unrelated interfaces sharing that numeric offset.

The next useful trace is to recover the +98 and +94 constructors' initialized vtables, follow `E020B0` and `E296F0` and their event registrations or control lookups, then trace concrete values from Cell gameplay state to verified control methods. Confirm the relevant calls and stack arguments in assembly and identify their actual interface implementations before assigning semantics. Separately establish provider initialization and package precedence, active visibility and runtime layout before using the candidate as a replacement HUD.

The note author inspected the existing dossier and decoded executable bytes read-only; no game code, Cargo or GPU was run. The dossier hash is provenance for the retained static analysis, not runtime evidence.
