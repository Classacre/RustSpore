# Cell source Creature mip-chain integration

The experimental Cell source-Creature inspection path now requests all declared mip levels from the exact saved sampler-zero standalone RASTER. `spore_core::raster::Raster::mip_levels` checks the source's base length and subsequent length-prefixed levels against format-specific extents. The Bevy bridge decodes each level to RGBA8, enforces dimensions and total decoded-size limits, compares the first decoded level with the previously resolved base texture, uploads levels largest first, and sets the image mip count and inspection sampler's maximum LOD. A source mip-filter value of zero retains a zero LOD clamp. RW4 textures retain base-only inspection when mip filtering is disabled; they fail explicitly when filtering is enabled because RW4 mip-chain handling is not implemented. A malformed or unsupported chain fails explicitly. Other source-art paths retain their previous base-image handling.

The retained controlled original-D3D9 log `target/source-creatures/native-corpus-v2/40616200A1C46DF2.log` identifies sampler zero texture `40612900A1C46DF2` as 512 x 512 DXT5 with ten mips and sampler one texture `40612901A1C46DF2` as 256 x 256 with nine mips. The existing controlled native renderer uploaded source texture blocks; its inspection camera, light and material assumptions are not evidence of a live Cell actor. The new Bevy path continues to render PBR and only the saved shared sampler-zero texture; it does not implement the native shader, sampler one, original material state, animation, selection or gameplay. Its RGBA sRGB interpretation remains an inspection choice.

Unit tests cover a two-level standalone L8 chain, level ordering and exact decoded extents, truncation and malformed lengths, Bevy image mip count and upload bytes, and the zero/nonzero mip-filter LOD rule. A subsequent synthetic DXT5 test covers odd 5 x 3 dimensions, mip pixels and a corrupt per-level size. The retained workspace test log `target/workspace-tests-20261030-resume-v51.log`, SHA-256 `9fd759e5f80fd8e011e398ddf67b3e56ce9a88bab90b63ba3de2979768a20a77`, records that DXT5 test as passing and aggregates to 771 passed, zero failed and two ignored across its test-result summaries. The log does not independently bind its test binary to a specific source hash.
