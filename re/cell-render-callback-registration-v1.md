Manual function boundaries, decompiler-inferred types and signatures, indirect calls, loader warnings and unresolved library links limit coverage. This is not REA Evidence or observed execution.

Thus a conditional registration-like call receives a pointer to an image object whose callback-table +0C is the previously traced Cell main-world render function; this does not itself execute that callback.

The earlier `cell-ui-parent-sizing-audit-v1.md` traces `67D870` to singleton `015FE8C0`, initialized through a Graphics constructor `75F840`. On successful standard initialization, unchanged singleton and vtable, the `E55043` virtual call consequently reaches `760180`. Runtime replacement, initialization failure, and actual invocation remain separate admissions.

`760180` passes the embedded address receiver +28 to `921C90`, walks its receiver's +8C/+90 range in 20-byte steps, and compares the supplied integer against each record's +4 as unsigned. For an equal key, it conditionally retains the supplied object using its virtual +0, prepares a 20-byte value, calls `75EC70` on the matching record, then conditionally releases the temporary object with virtual +4. For a missing key it prepares an analogous value and calls `75FF10` with the insertion position; that helper either appends via `75EDB0` or delegates to `75FB50`. `75EC70` conditionally retains the replacement before storing it and releases the prior object if different, then copies remaining record words. These are conditional source operations and require valid receiver, coherent sorted range, object and record lifetimes, callback side effects throughout the operation, and allocation success; the full insertion, lock, failure and concurrency semantics are not settled by this trace. A successful registration is not observed.

This supplies a source-backed path from the Cell caller to the keyed Graphics registration mechanism and the callback object for `E54B50`. It does not establish when the Graphics scheduler invokes the callback, whether registration survived replacement/removal, whether dispatch actually reached the model, or any order relative to `E806E0` world updates. The next trace must follow the +8C/+90 record consumer and its indirect +0C callback invocation, then identify its enclosing frame phase and synchronization before connecting update to draw. No GUI, original game execution, or GPU work occurred.
