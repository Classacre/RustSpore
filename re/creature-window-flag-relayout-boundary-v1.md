# Creature candidate window flags and relayout gate

Static evidence only for installed SporeApp.exe SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. PE-mapped instruction bytes and descriptor words are in `target/source-ui/creature-flags-v1/instructions.txt`. Candidate serialized records and duplicate copies are in `target/source-ui/creature-ui-graph-audit-v1.json`; no live UI selection or loader execution is claimed.

Image property descriptor records `0154FF58`, `0154FF70`, `0154FF88` respectively list `EEC1B001` type 9 offset +80 count 1, `EEC1B002` type 9 offset +84 count 1, and `EEC1B000` type 9 offset +2C count 1, matching the previously documented SPUI metadata pattern. These describe fields; they do not independently prove the generic loader writes these values or that callbacks leave them intact. Candidate objects 965/966/968/969 serialize B001 respectively `0190722E, 00000000, 0562A0F7, FFFFFFFF`; their B000 words respectively are `00000013, 00000413, 0000001B, 00000003`. B001 control identity and B000 flags are different fields and must not be conflated.

Under successful base Window constructor `9629F0`, `962A2C` clears the low nibble of byte +31 while retaining its high nibble; `962A33` writes 3 to +2C. Its list +64 is initialized empty at `962A65..962A6A`. This establishes initial +31 bit 02 clear, not the whole byte zero and not later state. `9614F0` clears +31 bits 02 and 04 then traverses its +64 list until the sentinel: a traversed node with +0C mask bit 100h sets +31 bit 02; mask bit 20h sets +31 bit 04. The routine separately derives bit 01 from mask bit 02 and may make an owner-dependent call when that bit changes. A valid terminating list, node lifetimes, registered listener masks and callback side effects are necessary. Other writes or later registrations are not excluded.

For an explicitly admitted fixture state in which child 966 is present in 968's child list, its B000 word has been loaded unchanged as `00000413`, its +31 bit 02 remains constructor-clear (or was recomputed from a valid empty +64 list), and the documented `960AC0` parent width/height-change loop is reached, neither child +2C bit 800h nor +31 bit 02 is set. The specific child gate therefore skips the virtual +94 call to 966. This does not decide whether the parent loop is reached, whether another route invokes 966, whether a procedure later registers, or what happens in a live screen. If a traversed listener mask has 100h at the point `9614F0` recomputes flags, the +31 gate can become true; serialized omission of B00C alone is not proof of an empty live list.
