# E56960 movement gate: native comparison preparation

This comparison isolates q804's complete 111-byte E56960 function from executable SHA-256 `17cf32b3e3adbcc7ed9c4e593c83b5d3deb3c675059b7ad9cbfd19192df5f87a`. The generator verifies the whole image through `SourceImage`, the routine SHA-256 `1bb2c41693ab1d0ba73d6f37256d38620d852b0e7f1ea9ddfaf0681a15895b31`, and the original 3.0 and 1.5 binary32 constants at 013EB96C and 01485FF4. It copies exact bytes to their original virtual addresses, without changing the game. Original bytes and generated C are confined to ignored `target/`.

The retained run at `target/cell-movement-gate-native-result-v1/report.json` compared 1,880 rows: all matched exactly on AL and timer binary32 bits, with no model rejections or mismatches. The eight explicit PC53/PC64 and rounding contexts used MXCSR 1F80. The linked host binary received independent static review; that review and the comparison do not establish behavior outside this corpus. The adjacent `target/cell-movement-gate-native-result-v1-hashes.json` records matching before and after hashes for the original executable, extracted bytes, generated host, both executables, generator, runner, adapter and public model; it records runner exit 0. The report pins the request, both replies and executables. Its request SHA-256 is `f3a44f254aa5f2041d880dba3c02a9dfa42ab75a37d04d7b8effdf34c33563ba`; the native host executable SHA-256 is `0996048fbbefbf28b79b2a8fb5af42f46e31d1fcf4893487614d5636ed3a57d1`. The generator manifest's `built: false` and `executed: false` describe its own preparation step, not the subsequent run.

The decoded entry reads `[esp+4]` as actor pointer and `[esp+8]` as binary32 delta; both exits use plain `ret`. The caller cleans eight argument bytes. Only AL is the return value. The actor occupies a static array with in-array canary bytes; input fields +08..10, +4C..54 and +368 are explicitly initialized. The host checks all other bytes in that array unchanged, ESP, the direction flag from captured flags, x87 control and TOP value, and MXCSR controls; sticky flags are intentionally excluded. A zero TOP value does not prove the x87 tag stack is empty. It saves/restores the caller's x87 image and MXCSR, initializes an empty x87 stack per call and sets CW to each masked PC53/PC64 and all four rounding modes. MXCSR is 1F80, the only policy admitted by the public model. This is a fixture environment, not a claim about retail thread settings. The source overwrites its stack argument slot with the stored distance; that is expected.

The binary request has ten little-endian u32 words: position xyz bits, target xyz bits, timer bits, delta bits, x87 CW, MXCSR. Native reply is AL and timer bits (two u32); adapter reply is status, AL and timer bits (three u32). The finite, bounded deterministic corpus exercises adjacent binary32 values around distance 1 and 3 and timer 1.5, signed zero, multi-axis rounded lengths, signed delta, and seeded vectors. Its tiny position/target and delta cases take the below-distance-one path: the timer is cleared and the function returns before the delta addition. They do not test a subnormal timer addition. All eight x87 contexts are crossed with every case. A model rejection is recorded separately and causes failure, as does any exact AL/timer-bit mismatch. No exception flags or unmasked exceptions, NaNs, infinity, aliasing, live actor integration, dispatch or animation selection are claimed.
