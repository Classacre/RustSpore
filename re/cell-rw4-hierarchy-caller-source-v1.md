Failure of either prerequisite returns 1. `776240` forwards five arguments to `7761B0` and converts a zero result into 1, a nonzero result into 0.
- `775F30` is another entry containing the `776002` call. When its incoming three-word key's first word is `FFFFFFFF` and `73D170` returns nonzero, it copies that object's +8/+0C/+10 and applies the same `68C2F0` transformation. Otherwise the incoming value remains the source for the downstream request. The calling code can therefore supply a key independently; its identity and successful lookup are not established here.

`68C2F0..68C311` modifies the value's third word: `(old & FFFF0000) | ((arg2 & FF) << 8) | (arg3 & FF)`. The calls above set its low 16 bits to `6100`; `7755F0` then writes `2F4E681B` to the second key word. The native archive key word order is `(instance-low, type, scope)` according to [the native archive-index trace](archive-index-native.md), which supersedes the older DBPF field labels. If—and only if—the three words copied from `73D170`'s result +8/+0C/+10 are already such a native key, this operation preserves instance-low, replaces type with RW4, and replaces scope's low 16 bits with `6100`. That object-field interpretation and the lookup provider are not established.

Model `DAE8CE17:2F4E681B:00000000` would transform to `DAE8CE17:2F4E681B:00006100`; candidate clip `60BDD177:2F4E681B:40606000` would transform to `60BDD177:2F4E681B:40606100`.
